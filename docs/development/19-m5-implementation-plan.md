# M5 实施计划：炉类与静态配方预热

M5 从两个地方着手。进世界后就可以准备静态配方知识，减少首次打开背包时的等待。炉类则要让熔炼进入现有合成链，例如用粗铁、燃料和原木，在熔炉与工作台附近做出铁镐。

## 静态配方预热

- 在生存或冒险模式启用配方书增强时，客户端收到同步配方后就在现有 tick 中分片构建同一份静态目录。构建、解码与浏览共用原有 2 ms 软截止，单个原版构建单元仍可能越过截止点。
- 预热只读取同步配方与已绑定标签。资源快照仍由支持配方浏览的页面请求。首个浏览租约只绑定服务端配方版本，使用目录前仍须核对指纹。切换菜单复用目录，配方或标签更新、服务端配方世代变化、断线按各自的失效路径处理。
- 服务端静态关系的存档缓存继续由原索引管理。回归需要从真实客户端进入世界，在尚未打开背包时看到目录就绪，并验证第一次浏览能够使用同一代目录。构建中断、世代切换和超限继续由知识 GameTest 覆盖。

## 炉类处理

### 首条纵向切片

先做普通熔炉到铁镐这条链。端点扫描记录匹配工作站能力，规划用一个有界账本同时分配熔炼材料、燃料和普通合成材料。服务端按真实配方与可用工作站重验，把加工步骤、扣料和产物交给现有整链事务。验证通过后，再沿这条路径加入高炉和烟熏炉的配方类型与燃烧规则。

炉类步骤表达原版单输入加工、燃烧 tick 和返还物。普通合成和炉类各按真实输入复验，共用同一需求展开、容量检查和提交入口。物品链、数量和 MAX 读取真实计量结果。新能力、配方数据和世界规则进入相应的快照、目录指纹与确认身份。尚不能用同一规则验证的客户端路线保持未确定，由服务端裁定。

### 先落实的执行边界

- **工作站。** 开工要求附近有获准使用、正在运行且空闲的原版匹配工作站。篝火和灵魂篝火须点燃，按配方时间烹饪，投入只有原料。原版炉槽、篝火食物位、燃烧进度、余火和待领取经验归原版管理。计时加工绑定已放置的方块实体，在原版占用工作站或篝火熄灭时暂停。
- **时间与燃料。** 每批按配方所需 tick 计费。高炉、烟熏炉除了有各自的配方耗时，也要按原版规则把该类型的燃料时长减半。所有燃料由同一账本预留，防止同一份木材既用于合成又用于燃烧。余火只在请求内结算并计入浪费。燃料比较限于预算内已证明可行的组合，长期路线与联合燃料优化见 [M8](01-roadmap.md#m8-智能路径与燃料优化)，本阶段内只要不是太离谱的燃料亏损或计算效率问题就都可以接受，就不会提前完成优化。
- **返还与经验。** 燃料返还容器、其他副产物和主产物共同参与容量检查。依赖真实炉槽状态的湿海绵取水留给原版手动加工。经验按完成的炉类配方与次数分组，按原版方式处理小数并奖励经验球。背包装入物品后才触发通知和经验。
- **规则。** 时间压缩默认开启，炉类批量上限默认 64，范围 1–64，按整条链的炉类步骤计数。两个值均来自世界设置。显式部分合成沿用已有四态与唯一的世界白名单。

### 计时订单

开启压缩时沿用现有同步事务，扣料后立即发放产物。关闭时仍通过原请求和确认入口，按精确来源即时扣除输入与燃料，并把收取的物品和已经校验过的方案写入服务端订单。每名玩家同时有一条计时订单，涉及的炉在加工完成前由该订单占用。普通合成仍可继续。

订单随实际绑定炉的 tick 前进。区块卸载、停 tick，或炉子被原版操作占用时暂停。关界面、移动或下线不取消订单，停服重启时从保存的进度继续。工作站在加工完成前被拆除时退回收取的物品，同一位置的新炉不会接手旧订单。加工完成后，成品与余料在主背包都能装下时一起放入。背包不足时保留待领取状态，腾空间后自动重试。已完成的订单即使炉子被拆除也保留成品。退款与成品只能领取其中一份。

原版 2×2、临时背包 3×3 和实体工作台的箭头旁共用同一份进度显示。悬停提示显示剩余加工时间、暂停或待领取原因。客户端进度消息只用于显示。持久订单、炉标记、玩家和材料来源各自沿原版正常存档周期保存，异常终止时各文件的写入没有跨文件原子保证。

### 验收(有待再补充，目前先放这)

1. 熔炉、工作台和分开放置的材料可以完成铁镐链。检查粗铁、原木、燃料、最终物品、余料和经验的实际收支。
2. 分别验证错误工作站、燃料不足、立即交付时容量不足、审阅后移走炉或燃料。开工前拒绝应保持零消费、零产物、零经验。
3. 高炉和烟熏炉分别验证配方专属工作站与燃料折算。多件与 MAX 计入燃料和批量上限。整链仍走统一确认与提交，校验失败时能恢复材料。

人工复测时，可关闭时间压缩，分别在三种界面查看进度。离开界面再打开，确认进度持续。离开炉子直到所在区块停止运行，回来后确认进度从暂停处继续。把主背包填满，等加工完后看“待领取”，再腾位置检查成品和余料。分别在加工中和完工待领取时拆炉，检查退料与保留成品的区别。

计量基础见[炉类与燃料](03-planner-semantics.md#8-炉类与燃料)。自动化仍从[测试入口](../../tests/README.md)执行。

### 配方链修复

- 羊毛需求直接接收符合颜色条件的材料。自动生产跳过重复染色，线制羊毛和指定颜色仍可用。材料只有一份时，多件请求须准确指出缺口。
- 铁矿与燃料够七次熔炼时，铁裤腿走七次熔炼加一次合成。少量铁粒不能替代整批的九粒，也不会为了凑铁粒自动制作装备再熔回去。已有装备仍可用于原版回收配方。
- 只有熔炉、粗铁和燃料时，在背包配方书的可合成筛选下仍可搜到铁锭。炉类根配方沿用原版同步集合，左键只查看详情，C 走原加工请求。
- 同一产物的合成、炉类和篝火路线归到一个按钮，各自保留配方 ID。详情图左上角显示当前已确认可用的工作站。
- 增强配方书去掉原版右键小窗。左键点击已解锁且适合当前网格的普通配方时沿用原版操作，其余配方打开详情。点击详情节点能查看不同做法的实际配方图样和所需工作站。设计取舍见 [ADR-0009](adr/0009-recipe-route-selection-in-plan-details.md)。


### 暂定性施工

- 目前营火和灵魂营火共用一个图标，原因是两者的配方完全一样，整体就是两个改了个图标，多显示一个貌似没有多少用处。
- 目前只能绑定和使用一个熔炉，是出于施工复杂度考虑的，后续改为均摊性使用多个熔炉，被拆了某一个就把工作摊给其他熔炉，不过要以件为单位，不能时间性均摊，否则违反游戏规则。
- 营火这个东西有并发性，目前没有实现。
- 目前没有锁定被使用的炉类，准确的来说是锁的不够彻底：正在占用中再手动使用会暂停正在完成的"订单"，同时不能有两份订单同时用。
- 部分新增描述偏工程性。
- 余火问题比较严肃，目前是直接不用有余火的炉子，判定正在忙，"订单"完成后剩下的余火也直接吃掉了，后续可能改成原路返回，同时下次使用时会考虑上一次留下的余火。(酿造台同理)
- 暂时炉类配方支持的比较简单，都是原料-燃料-成品的，海绵是原版最特殊的，他实际上算两个配方，区分有无桶，不过目前先完全不支持。(这和以前有意为之的不支持比如盔甲修复的配方，染色的配方，地图复制，烟花，盾牌装饰等不一样)
