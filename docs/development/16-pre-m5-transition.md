# Pre-M5 实施说明

- 目标版本：Minecraft 1.21.1 / NeoForge 21.1.235
- 前置状态：M4 结束
- 状态：已完成（2026-10-28）

本阶段在 M4 的规划和事务上补齐世界规则、部分合成策略和原版式设置界面，整理文档、测试和生产代码，并统一 CraftableMC 的项目身份。没有提前实现 M5 的炉类，也没有把 M6 的配方书呈现扩展或第二阶段 R1 存储设计当作现有功能。

这里说明最终行为和仍然有效的设计。要查实际运行过哪些测试、通过了哪些人工项目，见 [Pre-M5 验收记录](18-pre-m5-acceptance.md#closure)；请求到提交的实现细节和质量改动见[生产行为链与质量审计](17-production-behavior-audit.md)。玩家操作见[玩家指南](../user-guide.zh-CN.md)，维护和测试入口见[开发指南](../developer-guide.zh-CN.md)和[测试说明](../../tests/README.md)。

## 1. 世界规则与预算

- 世界规则由服务端持有，包括环境范围、末影箱入口、部分合成、余料交付、根配方次数和整链步数。个人模式与余料偏好都只能收紧。
- `crafting.maxCraftBatch` 限制根配方次数；`crafting.maxPlanSteps` 限制根和中间步骤的实际配方执行总数，默认 128，可设 1–256。客户端与服务端搜索、见证复验和提交使用同一有效值；续算与诊断不重新领取额度，负搜索证据不能跨步数上限复用。
- 256 是计划、见证与投影的表示上限。生成物账本按每步至多一份产物及九份返还物设独立上限，64 KiB 编码、估算内存、计算状态和时间仍各自受限。服务端单请求 8 ms、全服同 tick 共享 16 ms 的协作式额度不因调高步数扩张。超过限制就拒绝或返回未知。MAX 上限尚未确定时，只显示已经证实的可行次数，选中的固定数量仍须审阅。完整边界见[技术架构](02-architecture.md#browsing)。
- `environment.diagnosticCacheTicks` 默认 5、范围 0–20，0 表示不复用缓存；只影响 `/craftable environment` 诊断命令。普通设置和世界规则摘要不显示，NeoForge 专业页可改。它不控制浏览、详情的刷新速度，也不替代审阅、确认、执行的新鲜检查。

当前联机协议是 15，两端使用同一构建。世界是否允许部分执行从唯一 `directPreparation` 模式派生，规则和浏览快照不再另带重复开关。浏览租约与资源快照必须用同一次捕获的规则，不能在组装租约时退回默认策略。规则变化使身份不匹配的浏览证据、详情、MAX、见证和旧确认失效，不重建静态配方目录或缓存。旧字段与历史协议不作为兼容入口；升级开发构建前备份配置，按当前注册定义重新生成并核对规则。

## 2. 部分合成与免确认名单

世界和个人共用“部分合成设置”的四态定义，按下表顺序从严到宽取较严格的一档。世界通过 `crafting.directPreparationMode` 和 `crafting.directPreparationAllowedRecipes` 配置；个人只保留 `crafting.partialPolicy`，没有单独名单。

| 模式 | 对明确请求的部分合成的影响 |
| --- | --- |
| 禁止部分合成（`DISABLED`） | 不执行部分合成，完整合成仍可用。 |
| 全部需确认（`REQUIRE_CONFIRMATION`） | 可查看部分方案，执行前必须确认。 |
| 白名单免确认（`CUSTOM`） | 仅实际执行的每一步都在世界名单内时免额外确认，否则仍需确认。 |
| 全部免确认（`ALL_SUPPORTED`） | 已支持且通过校验的实际步骤免额外确认。 |

世界默认为“白名单免确认”；个人默认为“全部免确认”，只是跟随世界规则，不会放宽它。即使世界选择“全部免确认”，个人改为“白名单免确认”时也只使用同一张世界名单。程序按明确规则比较严格度，不依赖枚举序号；世界规则页显示服务端原值，不把应用个人偏好后的结果冒充世界规则。

默认名单明列 32 项原版配方：十种原木或菌柄制木板、两种木棍配方及二十种金属和矿物的存储转换。切换模式会保留名单；空名单不免确认任何配方，不回退到按配方形状隐式放行。恢复默认值才重新放回预设。名单保存完整的 `namespace:recipe` ID，至多 128 项、每项至多 128 字符，规范化后排序去重；合法但未知或不支持的 ID 暂不生效。同产物的不同配方分别判断。数据包同名替换后，名单仍按 ID 判断，管理员应检查替换后的配方，而不是假设模组会据材料自动重估风险。

单次 C 不会在完整合成失败后自动消耗一部分材料。部分执行仍须由双击等明确意图请求，再按每个实际步骤的冻结策略判断是否额外确认。名单不扩展配方支持，也不绕过解锁、工作站、来源权限、组件保护、实际配方验证、容量和事务检查。客户端的可行结果、未知结果和被截断的方案都不能充当执行授权。未来炉类须先完成燃料、耗时、返还物、经验和执行校验，才能接入，不因某个配方 ID 已在名单里提前支持。

## 3. 设置界面与详情交互

“选项 → 辅助功能设置”的入口叫“配方书”（Recipe Book），打开“配方书设置”（Recipe Book Settings）；键位分类和诊断显示使用同一游戏内名称，模组 ID `craftable` 和 NeoForge 列表名 Craftable 不变。入口用原版半宽按钮，末行右侧空着就补上，满行再另开左侧。主选项页不另加按钮；主页把六项个人设置直接排成双列，不设二级个人页。

- **可编辑世界：** 只有当前单人世界未开放 LAN 且 SERVER 配置已加载，才允许编辑并保存规则。规则页列七项标量和半宽白名单入口，不显示重读按钮。进入世界前普通世界入口禁用；换世界、断线或开放 LAN 后，旧页面及延迟回调不得保存。
- **远程与 LAN：** 只读当前连接及世界的权威回复。重读按钮和“完成”并排在页脚，读取中不重复请求；状态和错误由提示与旁白说明。未同步或超时不以本地 SERVER 配置补值，迟到回复不得越过连接／世界／请求序号。请求独立限流，不带库存、浏览租约或制作权限；远程 OP 也没有远程写规则的入口。
- **保存与高级配置：** 普通页用草稿，“取消 → 默认值 → 完成”分别表示放弃、重置草稿和校验保存已改项。进入高级配置再返回，普通页保留已改草稿，未改项读取新值；普通页取消不撤销专业页已保存的更改。普通与专业页共用已注册定义、校验、默认值和持久化，专业页保留原生 Undo/Reset 及实际写入门禁，不作为未来世界模板编辑器。
- **名单：** “部分合成白名单”仅在世界使用白名单模式且具编辑权限时可改；已同步的只读世界在该模式下可查看。普通页按名称、物品 ID 和配方 ID 搜索，配方显示“允许直接准备／需要确认”，切换即增删该精确 ID。目录未就绪时只显示状态，已存未知 ID 不丢弃；就绪后不支持的行只读。普通子页完成只合回父草稿，精确 ID 输入/增删单独留给专业页的“免确认配方 ID”。

两套界面共用双语选项和提示，数字范围与默认值从注册定义派生，正文只解释用途。名单提示按完整等价候选集合汇总重复材料，限制在视口内，不修改真实配方。控件身份、排版、待提交滑块和页面生命周期见[设置界面维护](04-compatibility-and-config.md#settings-ui-maintenance)。

### 物品链、数量与确认

沿用 Shift+C 的物品链详情。界面按当前目标和数量显示实际投入、产出和缺口，材质或中间配方改变后重算整条链。数量选择与 MAX 仍是预览，完整制作或部分准备都要走服务端的审阅与提交检查。

Pre-M5 补齐了确认就绪状态。同一资源作用域的租约过期时禁用操作，续期后及时刷新按钮。数量、配方、部分策略或个人余料偏好改变后，清理不再适用的预览、待投影 MAX 和未发送的旧意图。恢复原偏好需要重新审阅。若主产物能装下，只有世界和个人都允许时，实际溢出的余料才会掉落。

迟到的“需要确认”只在原请求所属的页面和菜单打开详情。关页可以取消尚未发出的操作，已发请求仍由服务端裁定。若没有收到制作结果，详情会提示检查背包并刷新，重试仍需玩家明确操作。实际回归见[验收记录](18-pre-m5-acceptance.md#scenarios)，审计中的行为修复见[代码质量审计](17-production-behavior-audit.md#lifecycle)。

## 4. M6 配方书呈现设计（未实施的扩展）

Pre-M5 冻结以下设计约束；原版配方书及现有详情仍按 [M4 合同](14-m4-implementation.md#browsing)工作，分类扩展、收藏、创造目录映射和新的按钮／槽位动画留给 M6。

- 复用原版分类入口。自定义分类、搜索、收藏和筛选只影响显示，不授予解锁，不改变服务端配方合法性。个人配方收藏不是 M8 的材料锁定、材料保留或路线黑名单，不成为求解成本策略。
- 创造目录只提供分组和排序。多标签物品须稳定归组并去重，目录缺项或数据重载时有明确原版回退；不因此在创造或旁观模式启用制作。
- 同成品且精确组件相同的替代配方可组内择优；不同材质或组件必须尊重当前显示或选中的成品。Shift+C 切换最终成品与切换递归原料是两种操作，切换后重算整链和消耗。
- 按钮输出轮播与合成格材料虚影属于不同生命周期；显示图标、颜色、Tooltip、旁白和 C 必须指向同一目标。分类、搜索、收藏或排序改变时重建显示作用域，单纯资源刷新保留上一列表、页码和位置，不按瞬时可行性跳动，也不先清成未知再闪回。
- 普通配方 Tooltip 只留简短键提示，进阶手势由键位与玩家指南说明。不新增常驻教学 Toast、首次进世界提示或独立主浏览器。

M6 实施沿用 `RecipeBookProjection`、`RecipeButtonTargetResolver` 和窄 Mixin，不复制整份原版页面。验收覆盖分类、搜索、筛选与收藏组合，多标签、缺项及重载回退，成品替代与变体区分，槽位虚影与连续 C。第三方和非标准条目的映射留待后续生态兼容，不属于本阶段交付。

## 5. R1 存储资源端点设计（第二阶段，未实现）

R1 解决已有内容怎样获准访问、定位和写回；M9 另解决可达性、检测几何和实体输入。当前仍需附近有已放置且可使用的末影箱才取得末影库存，附近已放置的原版潜影盒按方块容器处理。下列设计未在 Pre-M5 新增材料来源，也不承诺通用第三方能力。

### R1a：末影箱物品作为本人库存钥匙

- 保留末影箱世界总开关和现有方块准入。设计上，玩家持有末影箱物品或已授权工作环境中存在该物品，也可准入本人的 `PlayerEnderChestContainer`；无须查找远处方块，也不全世界扫描。主背包、当前网格／光标和授权附近容器检查实际内容；副手可作为钥匙资格，但不因此把装备或副手内容整体纳入可消耗原料。
- 基础来源先完成区块、权限、锁、距离和菜单校验，再检查其中的钥匙。末影库存不能凭自己里面的钥匙自授权，不递归搜索未授权来源。后续如支持便携内容中的钥匙，也只允许已授权且绑定的内部路径。
- 多把钥匙和可用方块只映射本人的同一个端点；不暴露他人库存，也不消耗钥匙来购买授权。每次新鲜检查重新确认，移出钥匙、权限丧失或菜单结束后不复用。若计划消耗最后一把钥匙，须定义事务内资格和排他规则，并覆盖审阅后移动、确认时撤权的情形。

### R1b：潜影盒、收纳袋等物品的内部内容

- 资源身份由真实载体根来源、精确组件指纹及内部路径组成。客户端只拿有界不透明来源引用，不能指定任意写入路径或持有活容器句柄。载体在背包、光标、网格或授权容器间移动后重新绑定，旧路径和多个包装视图不能重复计数。
- 先只开放明确支持的原版载体，为嵌套深度、载体数、总虚拟槽、输入数、同步字节及临时内存定上限，并在扫描、解码和执行处验证。非法嵌套、循环、超限或不支持内容保守拒绝。不为扫描内容放开组件保护，也不把同一载体整体和内部内容同时列为可分配材料。
- 每份原料只有一个真实根写集。明确父子组装顺序，主背包容量模拟包含已更新的载体，不能被后续发布的旧背包结果覆盖。提交前重验根、内部路径、精确组件、数量和权限；真正写回载体组件，不以修改脱离世界的栈副本冒充提交。
- 失败时恢复根载体与受影响组件前像；输入、成品、余料与掉落实体仍由同一个事务守恒。故障注入至少覆盖部分写回、载体移动、父子写入冲突与回滚失败边界。

前移 R1a 或 R1b 会改变第一阶段支持范围，目前并不考虑优先完成。
