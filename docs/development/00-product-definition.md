# 产品(也就是本mod，这个文档使用更为正式的方式形容)定义

想象一下，你只是想做几个活塞。你先打开箱子拿原木做木板，再翻箱子找圆石和红石。铁锭不够的话，还得找粗铁和燃料，等熔炉烧完。好不容易到了工作台，又发现圆石少拿了两块，只好回去再翻一次箱子。等活塞终于做够了，还得把多拿的材料放回去。

材料和工作台明明就在身边，做几个活塞却要来回跑好几趟，重复打开好几个面板。Craftable 想省掉的就是这些来回操作。

本文记录 Craftable 的设计和各阶段目标。Pre-M5 于 2026-10-28 收尾，M5 已进入实施。例子里的熔炼属于 M5，目前还得自己烧。
(另外至于多余的材料怎么办，现在更高版本的原版有铜傀儡，其核心行为是分类存放，后续可能会借鉴行为逻辑以自动将物品放回对应位置，具体实现和定义有待评估)

## 1. 产品定位

Craftable 是“基础操作压缩器”，不是玩法模组，也不是存储模组。

有了本mod，在工作区里，玩家可以先看看合成要用哪些材料、会经过哪些步骤，再决定要不要做。做不成时，mod会说明卡在哪一步。材料、燃料、配方、工作站和访问权限都要按规则检查。

核心公式是：

`可执行操作 = 玩家意图 + 当前可用资源 + 当前可用工作站 + 合法配方 + 访问权限`

具体表现是：

如果玩家能够在当前环境下，遵循既定游戏规则，通过一系列明确且可执行的操作达成某个合成目标，那么玩家就应当能够通过一次简单、明确的指令完成这一过程，而无需亲自重复其中的每一个步骤。

模组负责将玩家的目标转化为具体操作，而不改变完成目标所需的资源、时间、工作站及其他游戏规则。当目标无法完全实现时，应尽可能完成其中可行的部分，并明确反馈剩余的阻碍。

## 2. 不可破坏的产品原则

### 2.1 玩家中心

工作环境是临时的、以玩家为中心的视图，不是世界中的持久网络。离开范围后，资源和工作站立即不再可用。

### 2.2 手动可达

只有在当前状态下玩家理论上可以合法手动完成的步骤，才可被规划器采用。这里的“可达”同时包含：

- 资源存在且可提取；
- 工作站存在且可使用；
- 玩家满足配方和交互条件；
- 没有越过锁、领地保护、所有权或其他模组的权限；
- 所在区块已加载。

仅仅发现了一个实现 `IItemHandler` 的对象，不代表玩家拥有读取或提取权限。

### 2.3 等价消耗

便利不等于免费。每个成功动作都必须完整结算：

- 输入材料；
- 容器物品与配方剩余物，例如空桶；
- 工具耐久或催化剂；
- 熔炼燃料；
- 输出、副产物和经验；
- 工作站自身被适配器声明的状态变化。

### 2.4 服务端权威

客户端只表达“我想制作什么、制作多少、是否接受部分完成”，完整详情可附一份待验证的路线见证。服务端必须独立授权新鲜环境、按入口求解或验证真实路线、模拟容量并复验提交。任何客户端传来的槽位、材料数量、失败声明或成功结果都不构成执行授权。

### 2.5 可解释

失败不能只显示“材料不足”。至少要区分：

- 缺少哪些基础材料及数量；
- 缺少哪种工作站；
- 有材料但不可访问；
- 存在配方，但搜索预算、循环或兼容限制阻止了执行；
- 输出无处放置；
- 环境在确认后发生变化。

### 2.6 保守兼容

对语义已知的原版设施和显式适配的模组设施执行自动操作；对未知机器只展示“不支持的工作站”，绝不根据方块名、菜单外观或配方类型猜测并消耗资源。

## 3. 工作环境模型

一次环境快照包含三类对象：

1. **资源端点**：玩家背包、附近物品容器、玩家自己的末影箱库存，后续可包含可拾取的掉落物。
2. **工作站能力**：3×3 合成、熔炼、高炉、烟熏炉，以及第三方适配器声明的能力。
3. **动作提供者**：后续阶段的村民交易、剪羊等世界交互。它们不是普通配方，必须有独立的前置条件和副作用模型。

资源优先级默认为：玩家背包 → 玩家末影箱 → 普通附近容器 → 实体容器 → 掉落物。优先级可配置，但同一次计划中必须保持稳定。

### 3.1 初始可用性规则

- 只扫描已加载区块，不因一次合成请求加载新区块。
- 玩家背包始终属于环境。
- 末影箱方块只充当访问玩家个人末影库存的工作站钥匙；不会暴露其他玩家的数据。
- 普通容器必须能从某个合法面提取物品；双箱作为一个逻辑端点处理，避免重复计数。
- 未生成战利品的容器不得被静默探测或提前揭示内容。
- 第一阶段不递归扫描容器物品内部的背包、盒子或便携存储。
- 正在被移除、区块正在卸载或能力已失效的端点不参与提交。

解释上述倒数第二点:
第二阶段 R1a 实现持有或已授权环境中有末影箱方块物品，可作为访问本人末影库存的钥匙。
R1b 另行实现便携内容(例如背包中的潜影盒或者收纳袋)的载体身份、嵌套/去重、载体与内容互斥和事务写回/回滚。
两项尚未实现(未来实现)，不改变第一阶段边界。

## 4. 第一阶段用户体验

### 4.1 原版背包与 3×3 能力

附近存在可用工作台时，背包中的有效合成上下文按 3×3 处理，使原版配方书能够展示并直接请求钻石镐等 3×3 配方。

实体 3×3 已由 Craftable 的菜单与同步协议实现：不替换 `Player` 的库存对象，并覆盖客户端/服务端拓扑、创造模式、重生、切换维度和工作站失效。第二阶段再把更多工作站的必要界面或状态以原版风格接入背包，而不是一次性复制所有机器 GUI。

### 4.2 原版配方书入口

第一阶段直接增强原版配方书，复用其物品图标、搜索、分页、分类、配方切换、提示和无障碍行为。鼠标指向配方时，可以按 `C` 制作。对于按钮当前显示的成品，合成结论从原版二态判断扩展为三种。

- **可合成**：当前工作环境可以完成目标；
- **部分可合成**：无法得到最终目标，但可以安全完成对目标有用的有限中间步骤；
- **不可合成**：缺少材料、工作站、权限、输出空间或受兼容限制。

同一配方按钮中的不同成品材质分别判定。当前材质不可合成时，若同组有其他材质可完整合成，配方书应提示这一情况。快捷合成始终以按钮当前显示的成品材质为目标。

配方集合和「仅显示可合成」筛选使用实际的合成结论。配方目录来自客户端已同步的配方管理器，`ALL` 显示策略使用 Craftable 自己的可见集合，不向玩家批量授予原版配方解锁。


### 4.3 原版式反馈与设置

普通制作成功通过物品进入背包以及原版音效/动画表达，不为每件物品弹出文字。
玩家主动请求失败时使用右上角原版 Toast，并把重复失败合并；
未执行时的状态留在配方按钮与 Tooltip，复杂计划才进入可阅读面板。
调试命令输出到聊天栏。

设置方面 Craftable 只维护一套由 `ModConfigSpec` 支撑的配置定义与真值。
原版设置入口位于原版“选项 → 辅助功能设置”的可滚动列表，保持纯原版体验的设置。
模组列表保留完整 NeoForge 专业页。
两种样式共用注册项及其标题、默认、范围和校验。单人未开放局域网且 SERVER 配置已加载时，世界入口打开原版控件编辑页；远程或 LAN 只显示权威规则快照，未进世界时普通入口不可用。个人偏好不能放宽世界限制。检测方式、掉落物、实体动作和无等待处理等后续规则仍在所属功能实现后注册；辅助功能列表只承载入口，不内联玩法规则。


### 4.4 递归合成与部分合成

示例：附近有工作台，箱中有原木和钻石。玩家选择钻石镐后，系统可自动执行原木 → 木板 → 木棍 → 钻石镐，并把最终产物送入玩家背包。

当钻石不足时，系统可以准备当前目标确实需要且数量受限的中间产物，并明确提示钻石缺口。
比如上述例子中没有钻石，只有原木，需要两根木棍时仍执行“两块木板→四根木棍”的完整配方，余量归玩家，玩家最终获得2木板和4木棍并受到钻石缺口提示。
不得拆分原版产量，也不得为了“尽可能合成”而把所有原木都不可逆地转成木棍。

递归与部分必然会产生余料，余料处理上不强求一定要能装下。

### 4.5 无等待熔炼

附近有可用熔炉、原矿和燃料时，规划器可把熔炼作为配方链中的一步立即结算，并授予对应经验。

这项功能改变了原版的时间成本、并发产能、熔炉燃烧余量和经验球行为，严格说不是纯界面便利。
不过从行为表现上来说，这主要是节省了时间成本，同时避免了玩家在一个地方干等或在未来才能拿到结果，产品将它定义为“允许但可关闭的时间压缩”：

- 默认启用，以符合玩家中心的核心体验；服务端可为平衡或整合包规则关闭；
- 服务端拥有最终开关和批量上限；
- 关闭后仍可规划合成，但会提示需要等待工作站处理；
- 不把燃烧余量凭空跨交易保存，除非以后引入明确的虚拟热量账本。

## 5. 两阶段制作

### 第一阶段：可信且可用的核心

- 玩家背包和附近通用物品容器；
- 工作台、熔炉、高炉、烟熏炉等已知原版工作站；
- 原版配方书增强、三态显示和背包内操作入口；
- 单步与递归合成；
- 有界的部分完成与结构化失败诊断；
- 燃料、剩余物、副产物、经验和输出容量结算；
- 服务端补偿式事务、多人竞争保护和基础审计日志；
- 配置界面；
- 只围绕原版资源、工作站和配方建立可靠基线；
- 保留清晰的内部边界，但不为尚未开始的模组兼容提前设计公共 API。

### 第二阶段：更聪明、更广的工作环境

- 将更多第三方和非标准配方安全接入原版配方书；
- 更优的可逆路径、替代材料和燃料优化；
- `Z` 键安全撤销；
- 掉落物、实体库存；
- 末影箱物品钥匙准入及明确支持的便携内容端点；载体/内部材料互斥、去重和组件回滚先于启用；
- 可达性、视线和可使用性检测；
- 村民交易、生物互动等动作提供者；
- 第三方工作站适配器、兼容包，以及在背包中加入或兼容更多工作站的必要 UI；
- 更复杂的资源类型，例如流体或能量，仅在明确需求出现后评估。

## 6. 明确不做

- 不增加网络控制器、终端、线缆、磁盘或新工作站方块；
- 不自动加载区块；
- 不远程跨维度取物；
- 不绕过锁、领地或所有权；
- 不在第一阶段操控任意未知模组机器；
- 不保证找到数学意义上的全局最优合成方案；规划必须受时间和状态数预算限制；
- 不在客户端直接修改物品或经验；
- 不将“撤销”实现成免费复制或无条件返还材料。

## 7. 成功标准

第一阶段可发布版本至少满足：

- 单人与专用服务器行为一致；
- 钻石镐与铁镐示例均可端到端完成；
- 两名玩家竞争同一箱子最后一份材料时，不复制、不负数、不吞物；
- 配方循环、标签替代、容器剩余物和满背包均有确定结果；
- 常见半径下不会每 tick 全量扫描方块或造成可感知卡顿；
- 每次失败都能给出玩家可行动的原因。
