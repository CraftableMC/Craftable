# 兼容性与配置

## 1. 兼容等级

对外说明应区分四个等级，不能笼统写“支持所有模组容器/机器”。

| 等级 | 含义 | 当前 M4 基线 | 后续范围 |
|---|---|---|---|
| 原生 | 内建语义并进入持续测试 | 主背包/当前网格与光标、获准个人末影库存、可用原版方块容器、普通合成/工作台 | 炉类归 M5；物品钥匙/便携内容归第二阶段 R1 |
| 通用能力 | 通过 NeoForge 标准能力访问 | 不承诺任意第三方处理器已可安全执行 | 第二阶段按所有权/失效/提取契约验证 |
| 显式适配 | 对方或本模组提供专用适配器 | 尚无公开兼容承诺 | 按兼容模块逐个声明 |
| 未知 | 只能发现外观/配方，语义不足 | 不自动执行 | 无完整执行契约仍不自动执行 |

## 2. 第三方容器

NeoForge `Capabilities.ItemHandler.BLOCK`、`ENTITY` 和 `ITEM` 能覆盖大量存储对象，但第一阶段只默认启用方块容器。实体容器和物品内部容器在第二阶段加入，因为它们有移动、递归、所有权和失效问题，若贸然兼容可能会导致意想不到的问题，甚至造成严重的物品损失或刷取。

这里的能力契约是后续兼容要求，不代表当前已实现通用能力扫描。第二阶段 R1 单独解决末影箱物品钥匙准入和原版便携载体内容，M9 则解决检测几何/实体；两者不混同。载体身份/内部路径、嵌套上限、直接载体与内容互斥、组件写回及补偿必须先于启用，见 [Pre-M5 资源设计](16-pre-m5-transition.md#resources)。

兼容要求：

- 使用实际侧面查询，遵守 `extractItem(..., simulate)`；
- 处理能力失效；
- 不假定处理器实现 `IItemHandlerModifiable`；
- 不直接改槽位或复制返回的 `ItemStack` 引用；
- 对模拟不纯、返回数量异常或提交不一致的处理器熔断；
- 专用适配器可覆盖通用能力适配器；
- 方块名字相同不等于端点身份相同。

## 3. 权限与领地

能力 API 不负责玩家权限。第二阶段兼容方向是独立 `PermissionProvider` SPI，当前不据此提前注册空接口：

```text
ALLOW     明确允许
DENY      明确拒绝，立即停止
PASS      不知道，交给下一个提供者
```

服务端配置决定所有提供者都 `PASS` 时的默认结果。单人可默认允许，专用服务器建议对非原版或疑似受保护区域默认拒绝。

兼容测试至少覆盖：锁箱、旁观者、冒险模式、领地内非成员、队伍共享容器和玩家离线后的所有权变化。Craftable 不应通过直接能力提取绕过正常方块交互被取消的权限。

## 4. 第三方工作站

没有通用安全方案。兼容模块必须说明：

- 哪类配方可执行；
- 实际输入、输出、副产物与容器剩余物；
- 能量/燃料/热量/催化剂成本；
- 机器是否必须空闲、完整、多方块成型或拥有升级；
- 玩家权限；
- 批量与随机输出；
- 模拟与补偿能力；
- 是否允许时间压缩。

随机输出、概率副产物或会改变世界的大型机器，默认不进入递归规划，除非适配器提供确定的服务端执行契约。


## 5. 原版配方书增强

Craftable 不开发独立的类 JEI 风格主浏览器。第一阶段增强原版配方书：

- 保留原版搜索、图标网格、分页、分类、配方切换、提示和叙述；
- 附近有工作台时以有效 3×3 上下文展示配方；
- 显示三态、所需工作站、当前可制作数量和缺口；
- `C` 直接制作；
- 配方选择记忆。

第二阶段将更多第三方配方、村民交易和生物动作接入配方书，并在背包界面加入或兼容更多工作站 UI。

原生分类/配方收藏/创造目录映射排序及动画反馈归 M6，而非等待 M11。Pre-M5 先冻结显示身份/稳定页合同：个人收藏不等于 M8 材料锁定，分类不授予解锁，创造目录排序不启用创造制作，不同成品变体不能被同组择优替换。代码与 UI 验收仍在 M6。

## 6. 配置

### 6.1 当前已注册的服务端/世界配置

| 键 | 默认 | 范围/值 | 说明 |
|---|---:|---|---|
| `environment.horizontalRadius` | `8` | 1–16 | 水平检测范围；上限控制立方扫描体积 |
| `environment.verticalRadius` | `4` | 0–8 | 垂直检测范围 |
| `environment.diagnosticCacheTicks` | `5` | 0–20 | 仅供 `/craftable environment` 只读诊断短缓存使用；0 禁用，普通设置页已隐藏，不控制浏览/详情/创建 |
| `environment.includeEnderChest` | `true` | 布尔 | 需附近存在可用末影箱 |

`loadedChunksOnly=true` 是安全不变量，不开放为可关闭配置。当前扫描形状是水平/垂直分别限界的方盒。

当前世界规则（`craftable-server.toml`）如下；Pre-M5 新增有效整链步数及部分合成规则，未将历史 M4 的验收改写成新构建通过：

| 键 | 默认 | 说明 |
|---|---|---|
| `crafting.surplusDelivery` | `REQUIRE_SPACE` | 可改 DROP_OVERFLOW；主产物必须入包，仅溢出余料可以丢弃 |
| `crafting.maxCraftBatch` | `64` | 1–64 次完整根配方；根与中间实际步骤另受 `maxPlanSteps` 限制 |
| `crafting.maxPlanSteps` | `128` | 1–256 次整链实际配方执行，包含根批次与中间步骤；调高不增大时间、状态或内存预算 |
| `crafting.directPreparationMode` | `CUSTOM` | “部分合成设置”：DISABLED/REQUIRE_CONFIRMATION/CUSTOM/ALL_SUPPORTED，显示为禁止部分合成/全部需确认/白名单免确认/全部免确认；切换不删除白名单 |
| `crafting.directPreparationAllowedRecipes` | 显式 32 项预设 | “免确认配方 ID”：CUSTOM 中在表内免额外确认，不在表内需确认；最多 128 项、每项最多 128 字符；空表不免确认任何配方 |

`maxPlanSteps` 已接入服务端规则、两端授权快照身份、搜索、完整见证复验及最终提交检查。有效世界上限与固定 256 步表示/解析上限不同；根批次、时间/状态预算、64 KiB 编码和内存边界各自独立。调高步数不保证 MAX 能精确证明或规划必然完成，超预算仍是未知。配置改变使旧动态证据和确认失效。构建与实玩记录见 [Pre-M5 验收](18-pre-m5-acceptance.md)。

“部分合成设置”是唯一服务端部分行为开关。
DISABLED 禁止部分执行，
REQUIRE_CONFIRMATION 允许查看并确认部分方案，
CUSTOM 只按一张完整配方 ID 白名单判断是否省去额外确认，
ALL_SUPPORTED 对已支持且通过检查的实际步骤省去额外确认。
默认 CUSTOM，没有名单外的隐式结构许可。32 项显式预设包括普通木板、木棍/竹子木棍及部分存储转换；具体内容来自同一已注册默认值，管理员可编辑或删除。表中保存具体配方 ID，而非输出物品 ID；同产物的替代配方分别处理，合法未知 ID 规范化保留但暂不生效，不生成新配方支持。输入需含显式命名空间，表内去重排序；非法列表/超界沿同一注册 spec 校验/校正，不静默截短后授权。ID 被数据包同名替换时，只要仍是已支持且通过真实校验的配方，白名单仍按该 ID 生效；不再以旧结构默认替管理员判断材料风险。

项目尚未正式发布，不维护开发构建之间的配置兼容迁移。旧世界部分开关、双表及旧 CLIENT 三态不转换为当前规则，也不保留别名或纠正前挂点。更换开发构建前应自行备份配置，重新生成并核对现行模式和白名单；缺失或非法字段由 NeoForge 按当前注册 spec 正常纠正，不能把纠正结果当作旧语义已被保留。

个人 `crafting.partialPolicy` 采用同一四态模式，默认 ALL_SUPPORTED 表示不额外收紧世界，并不保证实际免确认。有效顺序为禁止部分合成 < 全部需确认 < 白名单免确认 < 全部免确认，个人与世界取更严格者；个人选择 CUSTOM 时仍使用世界唯一白名单，即使世界为 ALL_SUPPORTED 也按该名单收紧，没有个人 ID 表、个人规则同步或本地 SERVER TOML 回退。有效值冻结与确认失效仍走既有规则路径。

当前显式空白名单是有效配置，不因加载或保存而补入默认项；管理员可主动使用“默认值”恢复 32 项预设。非法列表、超界字段及未知配置键交由当前注册 spec 的正常校验与纠正，不增加第二运行表、迁移标记或独立文件读写流程。

切换四种模式均不清空白名单，普通页“部分合成白名单”与专业页唯一“免确认配方 ID”编辑入口仅在 CUSTOM 可用；切回“白名单免确认”后恢复原名单。每条链的所有实际执行步骤都须满足许可，搜索冻结与权威见证复验共用同一个不可变策略。单次 C 失败不部分消耗；个人 NEVER/CONFIRM、受保护输入、权限/工作台/解锁、真实配方验证、容量、8 ms/16 ms 与体量限制仍生效，unknown 不得转为执行权限。规则变化使旧动态结果和 token 失效，但不重建静态配方目录/fingerprint 或知识缓存。M5 炉类须完成真实燃料/耗时/返还/经验契约后才接入，不因 ID 被列出而提前支持。

`diagnosticCacheTicks` 只控制诊断快照复用，值 0 禁用。它不出现在普通配方书（英文 Recipe Book）设置页面、世界规则行和扫描摘要中，高级/Mods 完整配置页仍可查看。常规浏览、审阅、执行和确认始终新鲜校验，不能改用陈旧授权。NeoForge 配置缺少 section 或键时恢复注册默认值，数值超出注册范围时钳制到边界（例如 `maxPlanSteps=257` 校正为 256，0 校正为 1）；实际重载回归状态以本轮跟踪为准。

## 7. 配置同步与变更

- 世界规则由服务端拥有；客户端界面显示服务端有效值；
- M1.1 使用 NeoForge 内置 `ConfigurationScreen` 提供“模组 → Craftable → 配置”入口；它复用原版 `OptionsSubScreen` 风格、校验、撤销与默认值机制；
- 单人游戏可以从该界面编辑本地世界服务端配置；远程多人客户端不得用本地 `SERVER` TOML 覆盖服务器规则；
- M1 将完整扫描设置纳入缓存身份，范围、缓存时间或末影箱策略变化后旧快照不能复用；
- 客户端偏好不能放宽服务端限制；
- 配置项使用翻译键、范围说明和重启/即时生效标记；
- 开发构建不承诺旧配置迁移；缺失、非法及未知字段沿当前注册 spec 正常纠正，升级前自行备份、重新生成并核对规则。

### 7.1 设置界面维护

#### 入口、末行与页脚

“选项 → 辅助功能设置”通过 `ScreenEvent.Init.Post` 将 150 像素宽的“配方书”（Recipe Book）加入原版 `OptionsList`。入口使用 `mod.craftable.name`，主页叫“配方书设置”（Recipe Book Settings），与 NeoForge 模组列表里的 Craftable 名称分开。主页以双列显示六项个人设置，下方提供世界规则和高级配置入口，并说明个人偏好受世界规则约束。进入世界前仍可改个人设置，世界入口禁用。主选项页的布局沿用原版，辅助功能列表只承载导航入口。

辅助功能入口和世界页白名单入口共用 `NativeOptionRows.appendSmall`。末行只剩一个半宽控件时补右侧。满行、全宽条目或空列表时另开左侧条目。`OptionsListEntryAccessor` 只补原行的 `children`，保留 `OptionEntry`、左侧控件和 option 映射，确保 `findOption`、`applyUnsavedChanges`、焦点及旁白仍使用原对象。嵌套按钮只由列表负责注册和渲染，页面重新初始化时先确认入口是否已经存在。

| 页面 | 内容和页脚 |
| --- | --- |
| 个人设置、可编辑世界规则、可编辑白名单 | “取消 → 默认值 → 完成”，三个 100 像素按钮。世界规则页显示七项标量规则和白名单入口，诊断 TTL 留在专业页。 |
| 只读世界规则 | 规则值与白名单入口占用原列表，“重新读取规则 → 完成”两个 150 像素按钮并排放在页脚。读取状态、来源与错误由重读按钮的 Tooltip 和旁白说明。 |

| NeoForge 专业配置 | 沿用“取消（Undo）→ 重置（Reset）→ 完成”和原生保存机制。这里的 Undo 撤销已作的专业页更改。 |

#### 注册元数据与提示

`ConfigSettings` 和 `NativeConfigOption` 从同一个 `ModConfigSpec` 取得 `ConfigValue` 与 `ValueSpec`。原版半宽控件使用短标题和短值，完整说明留在 Tooltip。枚举候选经 `ValueSpec.test` 筛选，普通页和专业页的部分合成、余料等标签复用 `NativeConfigOption.display`，由原版控件添加标题。多个选项的解释各占一行，缩短中文说明以免句号单独换行。标题控件按当前视口重新设置宽度，以适配语言和缩放变化。

数字 Tooltip 的正文只解释该值的作用。`SettingTooltip` 从注册范围与默认值生成两行灰色尾注，供普通编辑和只读页共用。专业页按 `ValueSpec` 身份找到同一个注册值，为标签和控件追加相同尾注，同时让 NeoForge 跳过数值控件自带的范围说明。数值范围、默认值和诊断 TTL 仍由注册定义决定。

#### 草稿、权限与返回

滑块的待提交值仍由 `OptionsList` 管理。点击完成、默认值或离开主页进入子页前，使用 `applyUnsavedChanges()` 将待提交值送入草稿。完成时在滑块提交前后都检查编辑资格，随后由 `Draft.save()` 先校验全部候选，再只保存已改的注册值。取消或 Esc 直接丢弃本页草稿。个人和世界页恢复默认时，用同一草稿重建新页面，避免在 `OptionsSubScreen` 保留的布局上重复追加控件。

只有未开放 LAN、且 SERVER 配置已加载的本地单人世界可以编辑。普通设置的规则状态绑定连接、世界和集成服对象，当前请求还需匹配序号。远程或 LAN 页面以该作用域的权威回复显示数据，未同步或超时保持未取得状态。已在等待时禁用重复请求，远程 OP 也没有写规则通道。世界设置保存和进入高级配置会使旧读取失效，返回已初始化的父页由 `tick()` 补读一次，有效时无需周期轮询。

进入高级配置时保留普通页草稿，返回时从同一 spec 刷新未编辑项。专业页已经保存的改动遵循 NeoForge 的生命周期。取消普通页不会撤销它们。专业 SERVER 配置的 `Section` 子页继承父节捕获的连接和世界身份。标量写入、Undo/Redo、整节 Reset 创建的闭包以及名单提交都在实际写入前复查权限，控件的可用状态也按同一权限刷新。开放 LAN、断线或换世界使旧页失效后，退出只能返回，停止向父节传递修改状态或触发保存。此前合法的编辑不因此回滚。CLIENT 项仍可在远程、LAN 或标题界面编辑。

#### 白名单编辑与展示

世界处于 CUSTOM（白名单免确认）时才可编辑名单。普通页和专业页共用已注册的模式、名单、默认值和整表校验。切换其它三态时保留名单，已打开的编辑器仍要拦住行操作、默认值、提交和旧回调。专业名单的 Undo/Redo 也复查模式及世界权限，模式控件和有权执行的整节标量 Reset 仍可正常工作。个人选择只能收紧规则，不影响世界名单的编辑资格或世界页显示的权威值。

普通子页按产出物品 ID、配方 ID 排序，搜索可用物品名称、物品 ID 或配方 ID。一次最多呈现 256 条，超出时提示缩小范围。目录未就绪时只显示加载或不可用状态，已保存的未知 ID 留在草稿中。READY 后合法但未支持的 ID 显示为不可切换的条目。支持的配方用“允许直接准备／需要确认”显示当前规则，点击只增删当前精确配方 ID。默认值恢复注册预设，完成仅合回父世界草稿，父页完成才保存。

成本 Tooltip 保留配方 ID、投入、产量和切换动作。按完整、等价的候选集合累计投入，箱子的八个同类木板槽可以合为一组，不同候选集合和真实配方需求保持原样。界面过矮时只裁剪可见行，保留可容纳的身份和操作提示，再将 Tooltip 限制在视口内。旁白仍可取得完整提示。

精确 ID 输入、添加和删除由专业编辑器负责。NeoForge 235 的元素校验不能表达整表数量限制，必须通过注册 `ValueSpec.test` 后才把提议列表交给父节的 Undo 和 `onChanged`。需要空表时可从专业页移除所有 ID，显式空表按注册规则保留。

### 7.2 联机规则同步

当前使用协议 15，联机各端须使用同一构建。世界是否允许部分合成从 `directPreparation` 模式派生，`CraftingRules`、`BrowsingSnapshot` 和规则编解码使用同一策略。设置请求与响应只带有界的规则值及请求序号，独立限流。浏览租约和资源快照须匹配同一份规则，服务端拒绝基于旧规则的确认。各次规则调整与验证结果见 [Pre-M5 验收](18-pre-m5-acceptance.md)，当前传输边界见[技术架构](02-architecture.md#transport)。

具体界面与反馈决策见 [ADR-0003](adr/0003-vanilla-feedback-and-settings-surfaces.md)。
