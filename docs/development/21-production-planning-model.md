# 配方与生产规划模型（草案）

统一建模与 M5 工作站验收、M6 配方书改进并行推进。离线建模可以把工作站当作已知能力、占用和时间约束，把配方书当作规划结果的读者。模型与例证先独立验证，再据此制定配方和存储的接入契约。功能次序见[实施路线图](01-roadmap.md)，当前行为见[规划与执行语义](03-planner-semantics.md)。

## 1. 一次生产操作如何改变资源

用离散状态转换描述配方。状态包括实际物品及其数量、可访问来源、工作站与运行中的操作、交付空间、有效规则和剩余预算。每次操作先绑定具体投入，检查前置条件，再产生一个确定结果或按已声明的联合分布产生一个结果。计时操作的开工和完工各有自己的状态边界，开工投入与完工产出在各自阶段入账。

给定状态 $s$，一次已绑定的操作 $a$ 只有在前置条件成立时才可执行。记 $T(s,a)$ 为其后继状态的分布。对库存来说，每个后继都是「先扣这次实际消耗，再加该分支实际产物和返还物」，同时更新占用、待交付和预算。目标是关于状态的谓词，例如实际交付了至少七个指定组件的铁锭。确定性计划是一列有序操作，随机策略在每一步只能依据已经观察到的状态决定下一步。

| 维度 | 需要表达的情况 |
| --- | --- |
| 匹配与绑定 | 具体物品及组件、标签、跨槽约束、候选是否能完整枚举。形状可以影响匹配，也可以只是展示元数据。 |
| 投入 | 消耗数量、燃料与能量、工具磨损、需要在场或占用但不消耗的物品、来源权限与保留条件。 |
| 产出 | 确定产物、输入决定的变体、容器返还、经验、随机产物与可能完全没有目标产物的结果。 |
| 时间与执行条件 | 工作站能力、环境条件、权限、即时完成、计时、暂停、取消和交付。 |
| 配方之间的关系 | 同一成品的多条路线、标签抢料、共享中间件、自循环、可逆转换、有限增产、随机回收。 |
| 存储 | 实际库存、来源身份、别名、可提取量、内部路径、堆叠与容量、失效和补偿。 |
| 目标与限制 | 生产指定数量、证明最多可合成、按预算尝试、材料偏好、费用、时间、确定性或概率要求。 |

- **配方知识**由配方 ID、来源、重载世代和声明能力标识。它提供匹配、投入和结果模型，供预热、索引、求解与展示共享。工作站能力、执行时序与界面图样各有自己的含义，不能从网格大小推断。
- **规划**使用同一份资源账本和绑定后的物品身份。候选生产者关系可保守放宽以加速查找，执行见证必须引用具体绑定与合法步骤顺序。库存和授权的生命周期归环境快照。
- **执行**归服务端，使用现有提交门面。审阅结果或客户端证据只描述路线。提交时重新检查权限和有效规则、来源新鲜度、工作站、容量及预算，再扣料、记录结果和交付。适配器报告未知行为、结果边界不完整或能力不足时，当前路线保持未知或不支持。

原版已经支持带组件、自定义谓词等材料匹配。模型需要区分「给出一件物品后能验证」和「能完整列出满足条件的物品」，两者产生的不可行结论不同。[NeoForge 1.21.1 材料文档](https://docs.neoforged.net/docs/1.21.1/resources/server/recipes/ingredients/)

### 首轮建模的验证范围

| 模型输入 | 样本需要能独立描述和检查的内容 |
| --- | --- |
| 配方声明 | 命名空间和世代、投入角色及数量、匹配条件和是否能完整枚举、跨角色的约束、消耗或占用、工作站和时序、确定或联合分布结果。图样只用于展示，形状影响匹配时另设约束。 |
| 存储快照 | 可授权的访问路径、真实库存根、根内来源、精确物品与组件、可取量和版本、载体与内容的互斥关系、接收产出的容量。存储地址和授权令牌由执行端持有。 |
| 求解请求与证据 | 起始状态、目标、种子或材料保留约束、确定性或概率保证、步骤和投入限制、搜索预算。能重放已找到的路线，分别报告已证明的界、未知和不支持。 |

每种已纳入的语义至少有一个成功例和一个会暴露错误建模的反例。例如同源和同内容需要不同判断，概率联合结果需要能区分相同的单项概率。完整支持的输入，要求能判定某一步可否启动并描述其可见后继。无法枚举结果或验证副作用的适配器，应在对应能力上明确标作有限信息或不支持。首轮以这套范围作为 API 草案的评审依据。正式类型、编码、兼容承诺和游戏执行范围等验证后再定。

第一轮先取有限、确定性、来源可穷举的子集。配方和存储各用内联数据与试验提供方构造同一问题，并打乱提供顺序。独立检查器应能重放每条可行路线，精确的小实例搜索应能验证已证明的不可行与 MAX。受搜索预算限制时可以给出已验证的下界或未知。这个检查可以先离线完成。

### 联合产出

一次执行的随机结果是**一组一起发生的产出与其他效果**。确定性配方是只有一个概率为 1 的结果。保证产物可提为每个分支共有的部分，其余部分表示条件、互斥、关联、权重奖池或明确独立的多次抽取。例如「必得 A 并有机会得 B」「B、C 二选一」「只有 B 出现时才抽 C」使用同一语义。有用的空分支也须能明确描述。概率必须基于已绑定投入与声明的上下文，跨步骤独立性、保底和随机状态依赖都需要显式建模，首版可以拒绝超出已验证范围的机制。

概率可用紧凑的组合结构表示。预热与求解均限制枚举规模，需要保守投影时应保留其边界和已知程度。比如「等概率只得 A 或只得 B」和「等概率同时得到 A、B 或什么都没有」，单看各物品都有 50% 产出率，但两条配方对容量和后续配方的影响不同。边缘概率与期望数量不能进入库存或授权计算。若每种合法结果都保证目标足量，仅剩余物随机，在每种结果都能安全交付的条件下，仍可以证明目标数量。

## 2. 循环与有界求解

- **模板复制。** 输入一份模板和其他材料，输出两份模板。模板的净数量增加一份，但没有种子时第一步不能启动。先区分可访问种子和账面净变化，再核对复制材料、升级消耗和目标路线要求的种子留存。将这个例子保留为跨版本反例。
- **可逆与有损转换。** 铁锭和铁粒可按实际数量转换，羊毛染色仍可沿当前材料得到目标颜色。允许合法路线使用现有材料，剪掉有证明的无效往返，同一物品再次出现本身不足以剪枝。
- **多步骤增产。** 一组配方的净变化可用于求数量上界或找潜在循环。必须另行构造每一步投入均足够的顺序，并检查组件、共享材料、外部耗材、工作站、预算和容量。分析上的潜在无界产量也受运行时硬上限约束。
- **随机回收。** 一份黑石可筛出远古残骸与黑石子，四块黑石子重新制成黑石。黑石和黑石子的实际余额决定下一步。若每轮都有机会补回一份黑石，连胜路径可超过任意预先指定的次数。即使某个模型几乎必然终止，也未必有有限的最坏尝试次数。

先复用现有确定性快速路径和分片预算。在离线基准中分别验证以下优化，再按效果接入游戏。

1. 为已绑定的简单无环路线聚合需求。存在标签抢料时，可用匹配或流量模型筛选候选，但材料数量、跨槽约束、组件和共享来源仍由联合账本验证。
2. 用强连通分量定位循环。先检查种子可达性和限制增产的外部耗材，再决定是否展开。守恒式或整数规划可提供数量界、动作次数和候选路线；候选必须经过逐步顺序验证才形成可执行见证。
3. 对无法安全约简的部分保留有界搜索。记忆化须区分会改变后续可行性的资源身份、工作站状态、保留条件与预算。比较优化前后时保留共用材料、产出容量不单调、已有中间件可直接用、预算截断和路线禁用等反例。
4. 随机小实例用有限时域的状态展开求精确可达概率，按已观察结果选择下一步。游戏首版用有界的重新规划策略，仅在具备实际安全执行证据时推进。动态规划或近似策略能否改进路线，先由基准验证。

求解结果应区分可执行的已知方案、已证明的最优解或不可行、当前上下界、搜索未确定以及不支持的语义。给定当前资源和限制，只有较小数量的可执行见证时可报告「至少 K」，证明全部更大数量不可行或达到硬上限后才能报告确定的 MAX。不能因为某个数量放不下就直接排除其他数量。

## 3. 数量、尝试与停止

| 玩家意图 | 计划与界面承诺 |
| --- | --- |
| 固定次数 | 按原规则请求指定次数和可证明的目标数量。直接随机操作可以另行显示「尝试 N 次」及其已验证的投入上限和可能结果。依赖随机中间物的整链先用显式尝试预算，暂不把目标件数直接换算成投料次数。 |
| 最多可合成（MAX） | 在当前路线、资源、容量和世界上限内，给出有证据的确定性数量。对于有保证的随机路线也可以计算保证量；目标保证量为 0 仍可能有机会获得。成功概率、可负担尝试次数、期望产量可以作为独立信息。 |
| 尽可能合成 | 在有安全尝试路线时，数量滑块末尾提供独立选项。若固定上限为 64，它是这 64 档之外的一档，协议也将它作为独立意图。玩家确认投入和尝试上限后，在指定路线及预算内按实际产出继续。 |

模型区分根配方的执行次数和目标的最终可交付量。循环中可以消耗前一步产物，最终交付还可能要求留下种子。因此一次操作的产量乘以根配方执行次数只能用于满足相应条件的路线。做现行行为对照时，仍按现行请求语义解释数量。

「可尝试」适用于已验证有安全的可启动操作，且所选路线存在已知的目标产出路径，但目标量不保证的情况。它是对当前成品的额外结论。粉色仍提示同组另一变体可以合成，灰色仍表示尚无结论。配方书和详情用文字或符号说明新状态，颜色只是辅助手段。未验证到可启动动作、仅有统计期望、预算用尽或适配器能力未知时，不能据此标为「可尝试」。可尝试是否纳入过滤器默认视图，留待有原型后结合游玩决定。

第一版先做显式确认的单个即时随机阶段，再支持预算内的多阶段执行。确认应说明所选目标与路线、允许的随机投入、次数与总消耗上限、可能没有目标产物、停止与取消的效果。普通 C 快捷键和部分合成白名单不默认授予随机投入权限。部分合成的中间料准备仍受现有许可控制。

服务端提交前先确认所有声明结果都有合法交付空间，或已有可靠的有界待领取方案。互斥分支分别检查容量。首版可只接入能验证所有结果容量的操作。受理阶段后只由服务端抽取一次，将真实结果与该步提交身份绑定，后续仅从实际库存和结果继续。重试、重连、投递重发或提交后的取消不能重新抽取。重启后继续执行需要可恢复的结果和已提交步骤记录。无法提供相应恢复能力时，不承诺跨重启续跑。

预算同时约束尝试次数、资源、步骤、运行时间和每 tick 工作量，连胜或重规划都不续额。材料或容量不足、授权或世界状态变化、不能安全推进、预算耗尽或玩家取消时停止，说明已完成次数、真实产物和停止原因。取消只阻止尚未开始的步骤，已提交步骤的投入和结果继续有效。零目标产出本身不必立刻终止，已确认的后续尝试仍可按预算进行。若新路线需要超出已确认的消耗或改用未确认的随机操作，则暂停并重新审阅。

## 4. 配方 API 与工作站边界

配方接入界定可选操作，存储接入界定实际可用资源和容量。目标、成本顺序和预算另由求解请求定义，两种接入提供同一规划问题的输入。离线先用两份独立的声明验证语义组合和结果重放。游戏接入时，让原版与试验适配器走同一个发现、预热、确定性规划和服务端提交路径。

通过验证的确定性范围可作为版本化预览。公开部分包括命名空间与配方 ID、绑定和结果描述、受支持工作站、声明能力以及重载失效。联合产出先通过测试配方验证语义，等概率执行完成确认、结算和复验后再开放相应能力。求解器内部结构、任务和事务句柄留在内部。提供部分信息时，适配器显式声明用途和保证范围。

首版使用 Craftable 已验证的工作站和执行契约。单靠读取第三方配方注册项或声明名称不足以推断自定义机器的真实投入、权限和副作用。自定义工作站、交互动作和无法约束的执行回调另行设计，适配器也不会因注册成功就获得扣料或执行授权。

## 5. 存储接入

R1a 的末影箱物品钥匙与 R1b 的便携内容是两种不同的准入。前者为玩家自己的库存增加合法接入点，后者从已授权的存储根读取真实内含物。现有[资源约束](16-pre-m5-transition.md#resources)继续生效。

- 用独立测试来源先验证只读的存储模型，检查根身份、同源去重、合法可见范围、可取量、容量与失效。只读提供方可供模型验证，只有通过授权与事务验证的来源才能进入游戏中的可执行计划。
- 以实际后端为存储根，接入点只是访问路径。多个端口引用同一后端时只计一次，两份内容相同的独立载体仍各计一次。便携来源以根、祖先的新鲜版本和内部路径重新定位；共享后端或别名无法识别时保持不支持。按活动的祖先链检测循环，递归哈希或编码前先限制深度、节点数及同步体量。客户端只接收不透明的来源引用。
- 将载体与其内容的使用视为同一库存上的互斥选择。规划与扣料必须针对同一组件快照，重新检查载体、祖先与权限。一个根的多项修改先在副本上合并，自内向外回写，调用既有事务一次发布。异构根的写入失败必须有补偿，写回不能被同一操作的背包交付覆盖。
- 开放可写的存储 API 前，先验证原版潜影盒、收纳袋及一个独立的栈内存储适配器。栈内提供方交付有限的只读快照和可验证的副本变更，Craftable 负责授权、去重、预算和提交。跨接入点共享的网络库存要有明确的根身份、权限、快照版本和提取/补偿合同才可加入可执行库存。NeoForge 的物品处理器能力可用作接入手段；可访问方位和能力对象的失效不能代替这些约束。[NeoForge 1.21.1 能力文档](https://docs.neoforged.net/docs/1.21.1/inventories/capabilities/)

## 6. 最小反例与验证基准

先让最小实例给出可核对的预期，再用同一套语义做基准。原版数据随版本记录来源。随机配方、上限压力和故意失败的存储等由 Craftable 自造样本独立提供。现阶段不依赖第三方模组或其数据集才能复现实验。

| 样本 | 要证实的性质 |
| --- | --- |
| 多标签抢同一块木板、多配方共享中间物 | 同一资源只分配一次，能找出只能经替代选择实现的方案。 |
| 无种子/有种子的模板复制、铁锭与铁粒、羊毛 | 不能用循环安排虚构启动库存；能从真实种子启动，避免无效往返；能区分有界增产和理论无界。 |
| 牛奶桶返还、装备组件、燃料与容量 | 正确区分返还、消耗与纯占用，保留精确组件，容量非单调时 MAX 仍需证据。含恶意或过期见证的请求不得提交。 |
| 保底加副产物、独立抽取、互斥奖池和条件奖池 | 联合结果和目标保证量正确；所有支持的结果均可交付；零目标分支正常入账。 |
| 黑石回收、零产出、连胜、重复请求与取消 | 只花已确认的资源，在预算内停止，故障恢复与重发不重复抽取或交付。 |

首个组合样本使用两条配方。复制消耗一份模板和一枚钻石，产出两份模板。升级消耗一份模板和一份坯料，产出一件成品。起始有一份模板和两份坯料，并要求交付后至少留一份模板。若两个接入点都指向只含一枚钻石的同一个根，MAX 为 1。若是两个各有一枚钻石的不同根，MAX 为 2。没有初始模板时首次复制和升级都无法启动。

确定性求解先以现有规划器为对照，小规模用穷举可执行状态作为精确判定器，比较可执行率、最优或不可行证明率、错误结论和搜索截断。评估工程性能时记录首解/完成时间、尾延迟、内存、预算及硬件。随机小实例先枚举有限时域的实际分支并计算可达概率，把统计实验明确标作估计。固定生成器版本、输入、种子、预算和独立的见证校验规则。
