## 1. 模块与调用方向

只有一套规划和事务核心。客户端浏览与服务端主动求解使用相同的 `CraftSearch` / `ResourceLedger`；
服务端 `CraftingService` 负责权威检查，`CraftingTransaction` 负责一次物品提交。
客户端结果、图和缓存都不能直接执行。

```text
org/craftablemc/craftable/
  api/            内部结果枚举；尚不承诺第三方扩展 API
  environment/    环境发现、资源端点、授权快照、世代和诊断短缓存
  workstation/    已支持的原版工作站能力及其来源
  recipe/         已支持配方的规范化、共享静态知识与可重建缓存
  planner/        有界搜索、精确账本、有序步骤、见证验证及显示投影
  execution/      权威门面、容量模拟、唯一事务和短期交互会话
  network/        有界载荷、限流/耗时准入、浏览订阅及快照传输
  config/         服务端世界规则、个人偏好及注册元数据
  client/         配方书、菜单屏幕、详情、键位及两种设置界面
    recipebook/   原版投影桥接、动态证据库与客户端计算调度
```

写操作的方向是 `network → execution/CraftingService → planner + recipe + environment → CraftingTransaction`。网络处理器不能绕过门面扣料、发布产物或掉落实体。服务端显式审阅与本地不可用时的有界单目标回退仍有实际用途；被动目录和 MAX 在客户端计算。

世界读取、授权和提交在服务端主线程进行；
客户端协调器、结果库及页面状态由客户端线程拥有。共享核心只接收冻结值，不持有玩家、世界或活容器。
后台磁盘写入只接收不可变值，不能访问游戏对象。

<a id="ownership"></a>
## 2. 数据与状态所有权

| 数据 | 所有者、用途与生命周期 |
| --- | --- |
| `EnvironmentSnapshot` / `ContainerEndpoint` | 服务端本次扫描的授权来源与活句柄，仅在主线程短期使用；提交前重新检查 |
| `CraftingRecipes.Index` | 各端各自按运行时配方世代复用的规范目录和需求关系，不存玩家库存 |
| `PlanningInput` / `ResourceLedger` | 不可变求解输入与当前分支的数量、来源、预留、余量；分支整体回退 |
| `CraftPlan` | 有序的实际配方步骤及精确资源引用，不是通用机器动作 DAG |
| `PlanView` | 有界的说明与交互投影；不能作为扣料指令或权限证明 |
| `CraftingSessions` | 每玩家单调操作序号、授权来源值映射、一次性确认及短期充分失败证据；不保存跨 tick 活容器或长期可执行计划 |
| `BrowseSnapshotTransfers` | 服务端浏览订阅、准入、发送游标与轮转；不拥有执行权限 |
| `BrowsingSnapshot` | 客户端收到的最小授权值视图；只含允许披露的资源、容量、规则、解锁/工作站和不透明来源引用 |
| `ClientBrowsePlanner` | 当前连接/内容版本下的有限任务、续算与公平调度 |
| `ClientRecipeStatusStore` | 唯一动态证据库，区分完整证明、诊断与未知；详情/MAX 只保留少量方案 |
| `RecipeKnowledgeCache` | 仅服务端当前存档的可重建静态文件；不保存资源、权限、计划或令牌 |
| 设置草稿 | 当前页面的未保存选择；规则快照另按连接、世界和请求序号归属 |

内容相同、授权仍有效和执行仍允许是三件事。同内容复查可以复用计算，但不能继承失效来源的权限；传输进度可以避免接收超时，但不能延长合成授权。关闭菜单、换世界/连接、死亡、维度变化、配方重载及撤权分别由拥有者清理相关状态，迟到回复不能发布到新意图或新页面。

<a id="execution"></a>
## 3. 从请求到提交

```text
明确目标 / 数量 / 意图 / 序号（完整详情可附见证）
  → 网络限流、耗时准入与玩家模式检查
  → CraftingService 新鲜扫描、冻结有效规则并核对上下文
  → 普通请求/部分意图按需搜索，或验证完整见证并重建路线
  → 真实配方行为、资源贡献和主背包净容量检查
  → 提交前复验规则、来源精确栈、权限、工作站和额度
  → CraftingTransaction 提取托管、发布产物/余料、核验实体
  → 标记物品提交完成，再隔离执行统计、判据与事件通知
  → 仅向本次请求玩家返回结果
```

### 搜索、审阅与确认

单 C 只尝试一次完整根配方批次。双击的部分意图须关联同目标前一次服务端真实完整失败；首次成功后的失败、长按和客户端否定状态都不能创建部分许可。Shift+C 的详情只读，修改数量或配方只改变意图。

完整固定数量见证只证明某条具体路线可行。服务端用新鲜授权重绑来源，逐步调用真实 `matches`、`assemble`、`getRemainingItems`，核对依赖、精确输入、贡献、解锁、工作站和容量，再交给同一事务；不搜索替代路线。见证不证明 MAX 最优、完整不可行或部分安全，失败也不自动触发昂贵搜索回退。

服务端可复用自己最近 40 tick 的充分完整失败证据，但部分请求仍须新鲜核对资源、容量、规则和约束。同身份才跳过完整搜索；未知、过期或资源变化不能命中。扫描时、审阅时和提交前的重复检查分别覆盖不同时间窗口，不能以去重为由合并。

确认令牌短期、一次性，绑定玩家、菜单、目标、数量、有效策略、世代和已审阅摘要，提交尝试前消费。材料变体、步骤、收支、缺口或结果性质改变时重新审阅；关闭、断线、重载等使旧令牌失效。客户端只读显示见证不是令牌，排队但未发出的点击应能取消；已明确发送的提交不因关闭界面撤销。

### 唯一事务与失败

自动输入包括主背包 36 格、当前原版 2×2/工作台或本模组 3×3 的真实网格及光标；结果格、装备、副手和非当前网格不参与。物品及组件精确匹配，非默认组件材料默认受保护。

主产物始终进入主背包。`REQUIRE_SPACE` 要求全部交付装下；`DROP_OVERFLOW` 只允许余料先入包、溢出部分产生原版实体，部分前沿交付也算主产物。允许余料掉落不等于允许扫描地面物品。

模拟按净提取后的容量联合计算，不假设数量与容量单调。中间物可在本次有界同步事务内托管、后续消费后一次结清，不占每步真实背包空间，也不形成跨请求虚拟库存。

提取/插入失败按受影响来源的提交前像恢复；实体失败清理本次可安全恢复的精确实体，技术失败不能当作合法部分完成。成功提交后，统计、合成回调、判据和 NeoForge 事件按每次真实步骤通知；监听器异常隔离，不能退款或重试已经交付的事务。第三方观察器不保证看到逐步骤背包变化。

<a id="resources"></a>
## 4. 环境发现、来源和权限

当前使用有界方盒 `BOX`，默认水平 8、垂直 4。只读已加载区块，不强制加载；检查原版容器的锁、阻挡、未解包战利品和可使用性，双箱规范化后只计一次。附近可用末影箱方块可授权本人末影库存，不读取他人库存。

主动审阅/制作使用新鲜扫描。浏览采用事件失效与有界周期复查，覆盖漏斗及其他玩家操作；不每 tick 无条件遍历整个方盒。分片复制完成后再核对一致性，原子发布完整值，冲突只有限重试或等待稳定。`diagnosticCacheTicks` 只控制诊断命令短缓存，0 禁用，不控制配方书或详情鲜度。

来源引用在同端点/槽位复查时稳定；替换、失权、双箱重组及重新授权需要废止旧引用。跨玩家/连接隔离，客户端只收到不透明引用，不收到坐标、槽位写指令或未授权材料。相邻 tick 的菜单点击、漏斗和回调仍会改变物品，因此预览成功不能保证之后执行成功。

通用 `IItemHandler` 只是自动化接口，不等于玩家权限。目前没有通用第三方端点/领地提供者链，不能据接口存在自动放行。未来适配须同时明确所有权、实际可提取面、模拟副作用和补偿等级；无法确认时不能借 `null` 面或宽松扫描绕过限制。

<a id="knowledge"></a>
## 5. 静态知识与规划核心

共享知识附属于 `CraftingRecipes.Index`，保存产物、候选配方、规范化需求与材料选项的关系；相同需求共享关系，不共享数量预留。客户端从同步配方建自己的运行时图，服务端权威数据和磁盘缓存分别拥有，不增加静态图同步或客户端永久计划缓存。

客户端同步配方后即可在现有 tick 预算内预热静态目录，首次打开背包时复用已有进度。动态浏览仍在打开相应页面后请求授权快照，使用目录前核对服务端指纹。

静态图回答“怎样获得材料”，`ResourceLedger` 每次解决“这些材料如何分配”。先用现物，窄需求优先，缺口按真实完整批次展开；分支可回退，生成余量/返还物可供后续步骤。循环须有真实库存起点，精确逆转换剪枝不能误拒绝合法拆合或数据包改比例配方。搜索、见证和提交使用相同净变化边界，净零循环不算制作。

存在性闭包是 OR 候选、AND 需求的必要条件剪枝，不证明数量、容量或部分安全。真实候选仍检查每步权限、解锁与工作站；候选、深度或时间省略不能得出充分否定。特殊、动态或无法安全规范化的配方，不因拥有普通 ID 就获得执行支持。

支持范围仍限于 `minecraft` 命名空间、原版 shaped/shapeless 序列化器的普通配方，且须满足真实行为检查。客户端目录先与服务端支持/规范化语义指纹匹配，标签、保护/准备规则、输出和返还物语义均在其中；不匹配时不发布本地可行证据。

磁盘文件只含有界版本、语义指纹和 ID/关系值。指纹覆盖真实配方内容、组件、返还物、标签及规范化规则；读取后核验完整性并重新绑定。缺失、损坏、超限、失配或 I/O 失败都回到可重建索引。合成不等磁盘；写入合并、限频、临时文件安全替换，旧世代不能覆盖新文件。关菜单/资源变化保留静态图；重载即使内容相同也开启新运行时世代，使旧授权失效。

具体算法与边界分别见 [03 语义](03-planner-semantics.md)、[M4 共享知识](14-m4-implementation.md#knowledge)和 [ADR-0007](adr/0007-shared-recipe-knowledge.md)。

## 6. 客户端浏览、证据与预算

客户端在一份完整授权快照下调用同一核心。内容身份包含实际资源、容量、有效规则、保护、工作站/解锁和来源映射；扫描编号、时间戳、心跳及租期不进入计算身份。同内容只续期，保留已完成证据；真正内容改变使动态证据失效，静态知识不重建。

完整证据 `FEASIBLE / EXCLUDED / UNRESOLVED` 与可选诊断属于同一条记录。隐藏筛选先 `FULL_ONLY`，悬停/详情按需补诊断；充分失败可升级诊断而不重搜完整阶段，未知不能跳过完整判定。充分排除完整不等于拥有部分计划，诊断耗尽也不能覆盖已有完整结论。

刷新时保留的陈旧图标表只含状态、原因和列表顺序，以 `~` 标记待更新；不含计划或充分失败证明，不进入 MAX、见证与提交。显示表与结果合计有 2 MiB 上限，页面稳定不代表旧求解证据继续有效。

详情、候选、MAX 共用前台槽，另留隐藏槽；最多连续 3 个前台片后给隐藏 1 片，同时只推进一个任务。闭包、静态准备、搜索、诊断、投影和编码共用 2 ms/tick 软截止，每 tick 最多 64 次派发。MAX 的完成投影放在后续前台轮次，不挤入已耗尽的求解片尾。

续算保存原账本、frontier、visited 与累计支出，片额耗尽可以继续，阶段总额耗尽则停止为未知。换分类、切用途、取消后返回或续期不能补额；显式刷新可限流申请新尝试。普通目录只保留小型结论，悬停/详情最多两份方案，当前显示另附最多 64 KiB 的只读见证；后台 MAX 换槽不能抹去已发布显示的见证，失效或换意图则清理。

| 当前边界 | 作用 |
| --- | --- |
| 根批次 64；整链默认 128、配置 1–256、硬上限 256 | 包含根与中间实际步骤，不能用提高步数绕过其他限制 |
| 完整与按需诊断各累计 8 ms / 2048 状态；单需求最多 16 候选、深度 12 | 独立阶段预算，诊断不借额给完整搜索；不完备时不能授权部分执行 |
| 服务端单请求最多 8 ms、全服同 tick 共用 16 ms | 后台最多 8 ms并公平准入；扫描、验证等消耗实际余量，不每阶段重领 |
| 动作/详情编码 64 KiB | 字节限制独立于步数、内存和时间 |
| 单事务最多 32 个余料实体 | 超限整单拒绝，不能截断实际交付 |
| continuation 各估算 4 MiB，动态连接估算 16 MiB | 分配前检查、有限方案槽；不把估算当 JVM 堆硬保证 |

时间预算是协作软边界，无法抢占一次 Minecraft 回调，原子提交也不能做到一半就停。显示“至少可做 K 次/未确定”比把未知当 0 更准确；MAX 可用保守材料上界证书，但不把容量当单调函数。更多体量约束见 [M4 预算合同](14-m4-implementation.md#limits)，实测延迟与未测矩阵见 [M4 性能证据](15-m4-acceptance.md#performance)。

<a id="transport"></a>
## 7. 网络与快照传输

当前协议 **18**，各端使用一致 JAR。浏览沿用订阅、授权指纹和有界值分块，快照带加工工作站能力和世界规则。计时加工状态由服务端单独发给订单所有者，客户端只显示状态和进度。设置只读请求与执行请求继续沿各自的准入路径。

网络输入先验证身份、长度、数量、版本和频率，再进入主线程门面。快照不预留物品，不广播私密内容；菜单格仍走原版同步。

| 传输边界 | 当前合同 |
| --- | --- |
| 快照 / 分块 | 最多 4 MiB；每块数据 31 KiB、头至多 1 KiB，整块不超过 32 KiB；最多 133 块 |
| 发送准入与公平 | 全服 128 KiB/tick、玩家 32 KiB/tick；最多 8 份已准入传输，每份每轮最多一块、逐块轮转，满块全服最多 4 块/tick |
| 等待准入 | 最多 100 tick 等值；先完成数据/内存准入再发头，无名额只发有界等待消息，不提前大分配 |
| 接收内存 | 每连接一份已发布值和一份接收缓冲；完整长度、块数、摘要和身份验证后才原子发布 |
| 无进展 / 总期限 | 单调时钟按 50 ms/tick 等值；有效新块才刷新 100 tick（5 秒）无进展期限；总期限固定 `100 + 4C` tick，最多 632 tick（31.6 秒） |

关闭、重载、断线、超时释放缓冲；重复块、心跳和租期不续总期限，传完仍需新鲜授权。慢传输与普通浏览全范围收敛是不同指标。

### 停滞补传的当前接线

2026-10-23 的加固补上实际缺内容补传，不属于 M4 的 10-06 验收结果。非零会话的 `BrowseRequest` 配合 `resources=-1` 表示同一订阅缺内容；服务器只能在普通限流、准入和轮转下，对同一当前快照补传一次。

接收端仅在无进展但原固定总期限尚未耗尽时允许恢复；同内容的新头继承首次开始时间，不重置总期限。摘要失败、主动取消或总期限耗尽后不能复活；真正新资源版本先释放旧缓冲，再建立新身份。接收进度不续授权，也不重置求解额度。修复及真实停滞、取消验证见[生命周期审计](17-production-behavior-audit.md#lifecycle)。

<a id="interaction"></a>
## 8. 配方书与真实菜单

原版 `RecipeCollection` 在活动期投影为统一动态结果，退出时恢复原集合；显示全部配方不等于批量解锁。按钮当前展示的精确成品与组件决定图标、颜色、Tooltip、旁白和 C 目标，同成品替代可择优，不同材质成品不能静默互换。

`UNKNOWN/PENDING/KNOWN` 与业务状态分开，视觉由明确的 `RecipeButtonVisualState` 选择；未完成结果不伪装成不可合成。未变结果不重建页面，资源刷新保留上一列表、页码和位置；已失效的旧绿不能继续授权。可见/悬停提升优先级，隐藏目标仍推进。

详情沿用原菜单和槽位生命周期，不新增服务端菜单或执行图框架。图只整理真实依赖、来源和收支；等价合并须比较完整材料候选与路径，不能按图标相同虚构共享来源。换数量/配方立即撤销旧显示与排队确认，迟到回复必须匹配当前目标、修订及页面。

临时 `AmbientInventoryMenu` 继承原版 `CraftingMenu`，保留槽对象/ID并重定位网格、追加装备槽；屏幕复用原版配方书、人物、药水效果与背包资源。`Player.inventory` 和 `inventoryMenu` 不替换。工作台、距离、模式、存活或维度失效时关闭并依原版返还网格/光标；生存/冒险以外不请求、不计算，服务端独立拒绝。切回生存不自动打开背包。

公开 `ScreenEvent` 优先，必要 accessor/Mixin 只暴露或拦截窄边界，不复制整份原版屏幕。原版窄屏配方书遮挡背包的方式保留。

## 9. 设置与规则归属

- `SERVER` 持有扫描、末影入口、部分合成、余料、根批次和整链步数等世界规则；诊断缓存只供命令。
- `CLIENT` 持有显示、详细反馈、仅已解锁过滤、个人部分/余料偏好及双击间隔。个人只能收紧世界规则。
- `COMMON` 当前无注册项，确有跨端非世界规则再增加。

`ConfigSettings` 与 `NativeConfigOption` 从同一注册元数据派生类型、默认值、范围和枚举候选；原版式页面和 NeoForge 专业页共用 `ModConfigSpec`，不维护两套规则或持久化模型。辅助功能页只放自然补齐末行的导航入口。

普通个人/世界页使用草稿：完成时先全量校验再只保存改项；取消/Esc 不写，默认值也只是草稿。进入专业页后返回，保留普通页已改意图并刷新未改项；专业页已保存的修改不受普通页取消影响。

世界写入只允许配置已加载、未开放 LAN 的本地集成世界；打开和保存时都核对同一连接、世界、服务器及未开放状态。开放 LAN、断线或换世界后禁止旧页保存。远程/LAN 只读当前连接最近取得的规则值，刷新回复须匹配页面/请求序号，缺失/超时不能以本地 TOML 冒充服务器真值；未加载世界也不把专业页当未来世界模板。

`DirectPreparationPolicy` 表达禁止部分合成、全部需确认、白名单免确认、全部免确认四态，以及世界唯一的有界免确认配方 ID 表。个人同四态只作收紧，共用世界名单；只有白名单模式按成员资格免确认，不存在隐藏形状放行。两种界面编辑同一名单，普通页不承担精确 ID 编辑。

有效策略冻结后贯穿搜索、见证和提交，进入规则、浏览内容与确认身份。规则变化使不匹配证据、MAX、显示见证和旧确认失效；名单变化不重建静态配方知识或磁盘缓存，也不增加可执行配方类型。详细权限与保存合同见 [04 配置](04-compatibility-and-config.md)和 [Pre-M5 设置](16-pre-m5-transition.md#settings)。

## 10. 尚未实现的扩展边界

普通合成、炉类、营火、切石、下界合金升级和酿造共用足量规划与提交。计时订单单独保存已扣材料或待交付产物，由绑定的炉类或酿造台实际 tick 推进。见 [M5 订单生命周期](19-m5-implementation-plan.md#timed)。

生产与规划建模和 M5 工作站兼容与占用、M6 配方书呈现并行推进。完整模型确定后再制定接入契约。迁移已有定值路线时，须核对规划、预览、确认、扣料、交付和订单生命周期。概率执行和配方 API 按各自的验证结果逐步开放。见[配方与生产规划模型](21-production-planning-model.md)与[实施路线图](01-roadmap.md)。

后续机器必须先约定真实输入输出、时间/能量、催化剂、返还物、经验、权限与补偿等级，再接同一门面和部分策略。数据包不能代替复杂机器副作用的代码适配器，`simulate` 有副作用或无法合理补偿的动作不能直接纳入自动事务。

R1 验证末影箱物品钥匙的授权和便携内容的事务写回。存储接入的可写能力随事务验证开放。可达性与实体输入另行处理几何、节点预算和竞态。M11 用兼容模块验证工作站与动作适配，其公开契约以真实接入和安全验证结果定版。见 [R1 存储资源端点设计](16-pre-m5-transition.md#resources)与 [04 兼容性](04-compatibility-and-config.md)。
