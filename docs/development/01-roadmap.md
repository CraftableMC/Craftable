# 实施路线图

## 1. 阶段 0：可行性与契约原型

目标：先验证最危险的假设，产出可行性验证。

### M0 三个纯原版技术原型（已验收，2026-09-02）

1. **M0-A 原版配方书原型（部分通过，完成技术取证）**：悬停目标、有效 3×3 尺寸、`C` 请求和服务端状态显示均可注入；同时证实“额外描边”不会改变原版 `craftable` 集合与过滤，解锁集合不能承担 `ALL` 目录，伪装 3×3 尺寸也不能正确驱动 2×2 菜单虚影。
2. **M0-B 原版环境快照（核心路径通过）**：玩家实际验证箱子及其他原版存储容器材料均可被直接制作使用；锁、阻挡、战利品和竞争边界继续由 M1/M2 自动化覆盖。
3. **M0-C 直接合成事务（核心路径通过）**：服务端能从附近容器消耗材料并完成一次普通原版有序/无序合成；配方书显示异常不影响服务端权威执行。

验收结论：M0 作为“验证危险假设”的技术原型通过并关闭。三个已确认缺口转为 M3 的强制验收项；
详见 [M0 验收报告](07-m0-acceptance.md)。

### M3 原版配方书增强（已完成，2026-09-08）

实现契约及范围校准见 [M3 严格实施计划](12-m3-implementation-plan.md)，验证证据见 [M3 验收报告](13-m3-acceptance.md)。
A–G、虚影修正及 H 玩家反馈通过；连续切换分类后约 2 秒状态收敛、配置分类翻译缺失与旧日志单次服务端延迟作为非阻断跟踪项保留，另不保证零警告且无全负载性能保证。

- 复用原版配方书的图标网格、搜索、分页、分类和多配方切换；
- 从客户端已同步的配方目录建立独立显示集合；`ALL` 不依赖原版解锁集合，也不修改玩家解锁进度；
- 按可见页批量取得同一环境世代的权威三态，把结果写入配方集合筛选语义，而不是在原版红框外追加另一层颜色；
- 配方页打开、翻页或搜索后主动预取可见按钮状态，不以鼠标悬停作为首次出现绿框的前置条件；
- `showing craftable`、分类可见性、按钮样式、工具提示和 `C` 必须读取同一状态；
- 创建响应后将已有状态标记待确认，只主动刷新当前视图；输出容量是共享约束，因此不引入材料依赖图进行精细失效；
- 生存/冒险附近工作台时提供客户端与服务端一致的真实 3×3 背包，复用原版背包人物、纹理、装备位置；左键放置、虚影、结果槽和 Shift 点击使用同一槽位拓扑；
- 实体工作台的配方书同样增强；创造/旁观完全禁用菜单请求、按钮、状态预取和 C，切换模式安全返还，回生存须下次正常打开；
- 工作台消失、玩家重生/切维度/切换游戏模式时安全刷新或关闭菜单，不替换 `Player` 的库存对象；
- `C` 键执行一次配方；“制作最大数量”随 M4 的数量规划和输出容量语义实现；
- 可合成/部分可合成/不可合成三态及无障碍可区分样式；
- 建立统一反馈路由：状态留在按钮/Tooltip，普通成功不弹文字，主动失败使用可合并的原版 Toast，复杂计划进入可阅读面板；
- 通过 NeoForge 公开屏幕事件评估在原版“选项”页加入 Craftable 设置直达入口；入口只复用同一个配置页，不复制配置控件；
- 多人环境显示服务端有效规则摘要；
- 不通过批量解锁配方污染原版进度；`ALL/UNLOCKED_ONLY` 只控制显示策略。

验收：玩家不查命令也能完成钻石镐示例；材料分别位于背包与附近容器时，无需逐个悬停即可取得按钮状态，按钮状态、`showing craftable` 结果和 `C` 行为一致；成功创建后的刷新不出现虚假的短时红框；左键预览在实体 3×3 中无错位。

### M4 递归规划与部分完成（已完成，2026-10-06）

实施合同见 [14 实施说明](14-m4-implementation.md)，结果与证据见 [15 验收记录](15-m4-acceptance.md)。内容包括：

- 普通配方的有界递归、精确联合账本、多材料路线、固定数量与最大数量(MAX)；搜索不完备时明确保留未知，不以超时授权部分执行。
- 单 C 完整尝试、同目标失败后的显式双击部分准备，以及 Shift+C 的物品链、配方选择、数量与重新审阅。
- 单步和递归共用守恒事务，提交前新鲜复验；主产物入包，余料按有效规则收纳或受控掉落，技术失败整体恢复。
- 原索引上的共享静态知识与可重建存档缓存；授权内容版本下的同核心客户端分片浏览，完整固定数量见证经服务端验证后进入原事务。
- 完整证据与按需诊断分层、隐藏任务公平调度、累计预算和有限方案槽。

验收示例：1 原木+3 钻石得到 1 镐、2 木棍和 2 木板；无钻石时单 C 零消费，显式部分准备只做有用的最少整批材料，连续请求不重复加工。循环、容量、截断、来源与确认失效的反例及性能样本集中在验收记录。

2026-10-06 阶段结束。最终自动基线与两组真实客户端游玩测试通过，此前完整多人通过、最新补丁单人复测无问题；最新补丁查缺没有再次多人复测。协议 9、固定 128 步和当时三档部分策略属于该阶段，现行规则按 Pre-M5。架构取舍见 ADR-0006/0007/0008。

基础筛选的全范围收敛已纳入交付。低配、大目录、多人高 RTT 和长期尾延迟矩阵留给 M8，局部失效与历史启发式也未提前实现；另外测试是有限性能样本，不保证通用可行。

### Pre-M5 文档、设置与设计过渡（已完成，2026-10-28）

- 完成玩家与开发文档、原版式设置及部分合成规则。结合实际游玩和客户端回归，调整了设置的权限、布局、提示，以及物品链预览与确认的衔接。
- 整链步数世界配置 `crafting.maxPlanSteps` 已注册，默认 128、范围 1–256；有效值贯穿规则身份、搜索与见证。表示硬上限 256、64 KiB 编码及既有字节/内存/时间/状态预算各自独立，不因调高步数保证规划成功。
- `diagnosticCacheTicks` 仅供环境诊断命令使用，值 0 禁用缓存，普通设置 UI/规则摘要不显示；常规浏览和执行仍新鲜校验。
- 原版式个人设置使用可保存/取消的草稿，世界页显示最近读取的服务端只读快照；单人未开放局域网可编辑，远程/局域网只读，NeoForge Mods 保留高级回退。
- 已完成个人/世界同四态部分合成设置与世界唯一免确认配方 ID 白名单，两种界面共用注册定义，个人只收紧世界规则、不复制名单；切换不删除名单，规则入动态身份、同步与 token 失效，不重建静态配方知识，也不新增执行支持。
- 原生配方书分类/收藏/创造目录映射排序及动画/反馈先冻结合同，M6 实施；便携内容和末影箱物品钥匙按第二阶段独立 R1 设计，不扩大第一阶段资源范围。

设置和后续设计见 [Pre-M5 实施说明](16-pre-m5-transition.md)。三轮人工游玩、自动回归和未覆盖范围见 [Pre-M5 验收](18-pre-m5-acceptance.md)，独立缺陷及修复见[代码质量审计](17-production-behavior-audit.md)。

## 3. 第二阶段：智能与扩展

### R1 存储资源端点增补（独立子线，未实施/待排期）

- R1a：玩家持有或已授权工作环境中存在末影箱方块物品时，可作为访问本人末影库存的钥匙；保留既有可用方块入口，不全世界找远处末影箱，不从未授权末影库存自授权。
- R1b：潜影盒、收纳袋等明确支持的便携内容；先确定载体根身份/内部路径、去重、嵌套/同步上限、载体与内容互斥及组件写回/整体补偿，不能仅把内部物品平铺成普通来源。
- R1 不依赖先实现 M9 的检测几何或实体扫描；它解决存储所有权与写回，而 M9 解决环境检测范围/可达性及实体竞态。
- Pre-M5 仅冻结 [资源设计合同](16-pre-m5-transition.md#resources)。第一阶段仍不递归便携存储；若要前移实施，须另行确认范围变更。

### M7 安全撤销与历史

- `Z` 只撤销最后一笔仍可证明可逆的事务；
- 记录槽位变化、精确物品组件、输出位置、经验和端点版本；
- 任一相关状态已变化则拒绝撤销并解释原因；
- 初期只支持纯物品合成，随后再评估熔炼经验与世界交互。

### M8 智能路径与燃料优化

- 扩展性能观测：低配硬件、大目录端到端、多容器 × 多设备 × 高 RTT、长期 P99/堆峰值；明确尚未证明，不与 M4 普通功能/安全验收混淆；

- 可选成功路线提示：按重复/交替路线基准证明净收益后再做，只影响候选优先级，不保存执行授权；复用共享配方知识入口，与 M7 撤销历史分离；
- 可逆配方识别和惩罚权重；
- 原料保留偏好、收藏/锁定材料和配方黑名单；这是求解策略，不与 M6 的个人配方收藏浏览功能混同；
- 按请求批量联合优化燃料，而非逐件贪心；
- 向玩家展示选择该路径的原因。

### M9 高级环境检测

- R1 存储资源端点是独立子线，不把便携载体写回/个人末影准入混称为检测模式升级；
- `BOX`、`EUCLIDEAN`、`LINE_OF_SIGHT`、`REACHABLE` 四种模式；当前 M1 有界方盒扫描明确记为 `BOX`，不误称欧式距离；
- 主线程分时的有界可达性搜索；
- 方块变化、区块卸载、维度变化和玩家移动触发失效；
- 掉落物、运输矿车等实体资源端点；
- 拾取冷却、所有者、年龄和实体死亡竞态处理。
- 在世界规则中加入检测模式、距离/搜索预算、是否使用掉落物和是否使用实体库存；单人可编辑，远程多人只读服务端有效值。

### M10 动作提供者

- 村民交易：职业、等级、库存、补货、折扣、声望和输入槽语义；
- 生物互动：剪羊等显式白名单动作；
- 世界规则提供实体动作总开关，并为村民交易、剪羊等不同副作用动作提供独立子开关；未实现动作不出现在设置中；
- 每类动作独立定义前置条件、副作用、冷却、声音/统计和撤销能力；
- 默认不把任意右键交互自动转成“配方”。

### M11 生态兼容与配方书扩展

- 发布稳定的工作站/动作适配器 API；
- 为高需求模组编写独立兼容模块；
- 将更多第三方配方类型、村民交易和显式生物互动映射为可展示的原版配方书条目或动作条目；
- 在背包界面加入或兼容更多工作站的必要 UI、状态和配方分类；

## 4. 每个里程碑的通用完成标准

- 功能只在服务端验证后事务化提交；
- 新语义有单元测试，涉及世界状态的行为有 GameTest；
- 专用服务器验证通过，不只测试集成客户端；
- 玩家可见文本有 `zh_cn` 和 `en_us` 本地化键；
- 调试日志不泄露其他玩家私有容器内容；
- 没有每 tick 全立方体扫描；
- 新兼容逻辑失败时降级为“不支持”，而不是猜测执行。

## 5. 后续产品决策点

- 是否以及何时选择首批领地/权限模组与工作站模组；这不是第一阶段核心的前置条件。

这些选择不会阻止先实现服务端规划核心，但会影响 UI 和公开兼容承诺。
