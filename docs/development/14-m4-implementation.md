# M4 实施说明：有界递归、数量与安全部分合成

- 目标版本：Minecraft 1.21.1 / NeoForge 21.1.235
- 前置状态：M3 完成
- 状态：M4 于 2026-10-06 完成。测试批次、失败修正及证据范围集中在 [M4 验收记录](15-m4-acceptance.md)。

<a id="scope"></a>
## 1. 范围与阅读边界

M4 将一次普通配方扩展为有界的整链制作，加入固定数量、MAX、安全部分准备、可编辑物品链，以及同核心客户端浏览。它继承 M1 的授权来源、M2 的补偿事务和 M3 的配方书/菜单入口，仍以普通原版有序、无序合成为支持范围。

本页的阶段基线是**协议 9、最多 64 根批次、最多 128 次实际配方执行**。128 次包括根目标与中间步骤，是 M4 当时固定的表示和执行上限。
Pre-M5 后续升至协议 15，并将整链步骤改为默认 128、可配置 1–256。现行依据见 [Pre-M5 设置](16-pre-m5-transition.md#settings)、[当前架构](02-architecture.md)和[配置规则](04-compatibility-and-config.md)。

M4 当时的 `NEVER / CONFIRM / EXPLICIT_SAFE` 三档策略、默认 `EXPLICIT_SAFE` 和代码内的保守安全名单，已由 Pre-M5 的四档“部分合成设置”和服务端配方 ID 白名单替代。个人设置仍只能收紧世界规则，名单由世界持有；不能把本页的旧默认策略当作当前配置说明。

主要决策保留在 [ADR-0006](adr/0006-m4-bounded-planning-and-chain-transaction.md)、[ADR-0007](adr/0007-shared-recipe-knowledge.md)、[ADR-0008](adr/0008-snapshot-scoped-client-planning.md)。日常开发和运行测试请使用[开发指南](../developer-guide.zh-CN.md)与[测试说明](../../tests/README.md)。

## 2. 玩家行为与目标语义

### 2.1 完整、部分与详情是不同意图

- 单次 C 尝试一次完整根配方批次。失败不扣料，也不会顺带制作中间物。
- 同目标的首次完整失败后，释放按键并在双击间隔内再按 C，才表达部分意图。服务端关联前次操作序号、目标、菜单和实际失败结果；第一次成功后的第二次失败不能触发部分准备。
- Shift+C 打开原菜单中的只读物品链页。浏览、改配方和拖动数量都不消费；只有明确提交当前已审阅意图才进入执行。
- 搜索框等文本焦点不拦截为合成快捷键；长按不视为双击。迟到结果必须匹配当前页面、目标及修订序号。

根目标由具体配方、精确产物及组件、根批次数、完整/部分意图、用户手选约束和余料策略共同确定。已经拥有最终成品不会抵扣本次新制作要求；已有中间物可以直接满足依赖。

### 2.2 批次、材质与手选约束

数量表示根配方执行次数，不是可拆分的物品件数。例如木棍 1 次产出 4 根，3 次产出 12 根；中间配方也按完整批次制作，取整余量真实保留。

原版按钮轮播时，C、颜色、状态与缺口都围绕当前展示的**同物品、同组件产物组**解释。同组的多种生产配方可自动择优，产量可以不同；船等不同材质成品不能静默互换。全组均不可制作时，已有可靠“材料齐全、仅空间不足”结论的路线优先于缺料或未知路线，避免误导缺口。

详情允许显式选择其他根配方或最终成品变体。切根后保留期望批次数，清除旧子树约束、计划及 MAX，再整链重算。根候选当前项优先，最多 16 项，超出明确显示截断。

节点手选配方是约束，MAX 也不能自动解除。选择作用于稳定的需求路径；上游拓扑改变后失效的子约束需要清除并提示。“恢复自动”由玩家显式操作，选择本身不执行。

### 2.3 部分合成的成立条件

部分结果分为“完成固定 N 次中的 K 次”和“为剩余目标准备有用中间材料”，详情分别表达实际交付与尚未完成的目标。完整计划始终优先。

只有充分证明完整制作因可取得材料不足而受阻，才可进入部分分析。缺工作站、未解锁/无权限、不支持的配方、容量不足或搜索不完备都不能授权准备材料；某个分支失败仍应尝试其他合法分支。

有用前沿属于当前所选目标依赖路径：先预留现有中间物，再补未满足需求，只制作所需的最少完整批次，并交付新的目标或中间材料。先完成可完成的根批次后，剩余缺口按新账本计算，不能再次计入已用于成品的原料。

例如工作台旁有 1 原木、没有钻石，显式准备钻石镐材料可得到 4 木棍及 2 木板，钻石仍为缺口。若这些木棍仍可访问，再次请求不会继续耗原木制造多余木棍；移走或使用后才可能需要重新准备。去重来自当前资源，不建立长期“上次任务”。

M4 的历史三档只在显式部分意图下生效：禁止修改、先确认，或安全名单内免确认/名单外确认；两端取更严格者。非默认组件材料受保护，复杂返还物不能仅因属于普通配方就自动认定安全。后继策略见第 1 节。

### 2.4 固定数量与 MAX

固定数量和 MAX 使用同一联合资源账本。不同批次可混用未固定的中间配方，不能把单次链乘 N，或把每条路线各自的最大量相加。

MAX 只计算完整根目标，不额外准备材料。容量随消耗、堆叠及返还物可能非单调，不能无条件二分；某个数量失败不证明更大数量失败。未证明上限时保留已证明的下界，显示“至少可做 K 次/上限未确定”，未知不是 0。

选择数量需要改用混合路线时，先更新组合链与净消耗并提示 `!`，经确认后才执行。服务端条件变化导致数量降低时，也应更新页面等待确认，不能静默缩量提交。

## 3. 同一个求解核心与精确资源账本

### 3.1 职责划分

| 职责 | 所有权与结果 |
|---|---|
| 配方索引/共享知识 | 规范化普通配方及输入需求，提供稳定生产候选；不分配玩家物品 |
| `CraftSearch` | 确定排序的需求驱动回溯，完整与按需诊断共用状态机 |
| `ResourceLedger` | 当前分支的数量、来源、预留、生成批次、余量及返还物，可整体回退 |
| `CraftPlan` / `PlanView` | 前者是有序实际步骤与资源引用；后者是有界执行/解释投影 |
| 客户端浏览协调器 | 持有当前不可变资源版本的有限任务、证据与调度额度 |
| 服务端门面/事务 | 新鲜授权、规则与见证验证，最终提交及失败恢复 |

共享核心接收冻结值输入，使用同一 `run`/可恢复 `advance` 语义。世界扫描、注册表和真实配方行为在游戏线程边界取得或校验；核心不持有玩家、世界或活容器，也未另建近似客户端数量算法。

### 3.2 需求展开与真实配方行为

先使用现物，优先处理更窄的输入条件；缺口按完整配方批次展开。账本分支可回退，通用标签材料不能贪心吃掉另一需求唯一可用的特定物品。生成的余量和返还物可以满足后续需求，同一木棍或空桶只能分配一次。

支持范围限于 `minecraft` 命名空间、使用原版 shaped/shapeless 序列化器的普通有序/无序配方，且非特殊、非不完整。这些必要条件仍不能替代真实行为验证：实际输入满足 `matches`，产物和返还物来自 `assemble`、`getRemainingItems`；数据包覆盖后的配方也受相同边界与预算约束。

每个有序步骤对应一次真实配方执行；不能用乘法省掉逐次返还物和回调。现物优先、低损失存储转换、预计动作数、端点顺序与稳定 ID 只用于确定候选顺序，不宣称全局最优。

工作站需要当时存在并可用，工作台物品不等于工作站，也不自动放置。`doLimitedCrafting` 下每个必要配方都须在请求开始时已解锁，不能假设中间步骤会即时解锁后续配方。

### 3.3 闭包、循环与守恒

材料存在性闭包采用 OR 候选、AND 需求，是必要条件剪枝，不证明数量或容量。闭包中的权限可放宽以免无材料起点的锁定备选误报目标锁定；真实候选展开仍逐项检查权限、解锁与工作站。返还物可达性也需覆盖，关系不完整时保留未知。

循环依赖按需求、数量和账本上下文处理。无库存起点的铁锭↔铁粒不能自行启动，有真实铁粒时应允许转换。精确逆转换剪枝仅适用于固定单一材料、默认组件、无返还物且数量完全互逆的相邻往返；修改比例或产生返还物的配方不套用。

搜索、见证重放和提交前共用净变化检查：按物品及组件比较提取与全部交付，净零循环不算可合成，避免空转刷统计。1 铁锭变 9 铁粒是合法转换，不能用跨物品总件数判断守恒。

请求内 memo 有界且匹配完整状态。候选、深度、内存或时间省略均不得缓存为永久无解；已保留路线仍可证明具体完整成功，未找到时若证明不全则停为未知，不能降级部分执行。

## 4. 授权、唯一事务与完整见证

### 4.1 输入来源与容量

自动取材范围包括主背包 36 格、当前原版 2×2/工作台或本模组 3×3 菜单的真实输入格及光标。结果格、非当前网格、装备与副手不参与；网格/光标只提供输入，最终交付仍进入主背包或受控余料掉落。

非默认组件栈继续受保护，包括名称、附魔、损伤及容器内容等；精确组件参与匹配和容量合并。不为诊断读取未授权来源，也不把锁定容器内的材料写进缺口说明。

容量按净提取后的主背包联合模拟：`REQUIRE_SPACE` 要求主产物和余料全装下；`DROP_OVERFLOW` 只允许余料先入包、溢出部分生成原版掉落实体。主产物始终必须装下，部分前沿的交付也是主产物。

中间材料可在本次有界同步事务内托管，后续消费后一次结清。这压缩了临时搬运空间，不要求每个中间步骤占据真实 36 格，也不形成跨请求虚拟库存。栈、数量、步骤和掉落实体仍有界。

### 4.2 一次提交与时间边界

普通单步、递归、部分计划和完整见证最终经过同一事务：新鲜扫描 → 规划/重建与容量模拟 → 复验模式、菜单、世代、规则、权限、工作站及精确来源 → 备份受影响来源 → 托管提取 → 发布产物/余料并核验实体 → 标记提交 → 逐步通知。

提取或插入失败恢复整份提交前像；实体失败还需清理本次可安全恢复的精确实体。技术失败不能包装成合法部分完成。扫描、审阅、提交前的再次检查分别覆盖不同时间窗口，保留它们是必要的鲜度保障。

原版统计、配方判据和合成事件按真实步骤与产量在全部物品提交后通知，包括已被下游消费的中间物。各监听器异常隔离并继续剩余通知，不能退款、重复提交或重试已交付事务；不保证第三方监听器看到逐步骤背包变化。

一次成功操作只要使用了 3×3 配方，工作台交互统计增加一次；多批次不重复增加。仅 2×2、浏览、失败、回滚、重复确认均不增加；物品合成统计仍按各实际步骤记录。

### 4.3 完整见证的服务端重建

客户端可提交完整、固定数量的普通配方路线见证，减少重新搜索；它只证明“存在一种做法”。部分安全、完整不可行和 MAX 最优性仍需各自证据，客户端失败结论不能授予部分执行。

见证包含作用域/版本、操作序号、根目标与批次、有效策略及约束、有序配方 ID、具体网格材料和授权来源/前序产物引用。不接受世界坐标、槽位写指令、自报产量、任意组件数据或可执行代码。

服务端先限长和限流，再新鲜授权并重绑来源；逐步骤调用真实配方行为，用同一账本重建提取与交付，检查解锁、工作站、精确输入及手选路径。引用只能指向已授权来源或已验证的前序步骤，计数需防溢出。

反向贡献检查确保每步服务于目标，拒绝无关加工、净零循环、虚增批次及刻意制造余料。中间生产须锚定实际需求，但执行中首次使用可以属于另一共享需求；未用中间产量须小于对应最小整批产量。随后重算最终容量，交给原事务，不另搜替代路线。

见证或预算失败为零写入，不自动转为昂贵回退搜索。无见证的普通 C、部分和必要主动回退仍由服务端核心处理；M4 退役的是被动逐目标/MAX 网络查询，而非这些实际能力。

### 4.4 审阅、令牌与失败证据

确认令牌短期、一次性、每玩家最多一份，M4 有效期 200 tick，绑定玩家、菜单、目标、数量、策略、世代和已审阅摘要；尝试提交前消费。关闭、死亡、换维度/菜单、断线及重载清理关联状态，活容器不跨 tick 保存。

材料变体、消耗、步骤、产物、余量、缺口或完整/部分结果改变时，返回新摘要并要求再次确认。完整见证允许用新鲜验证替代重新搜索，不能替代当前世界检查；普通提交和确认都不自动重试。

服务端仅保留每玩家最近主动目标、最多 40 tick 的自产充分完整失败证据。部分请求新鲜核对资源、规则、容量与约束，身份相同才直接进入诊断/部分阶段，完整搜索次数应为零；过期、换目标或证据不完整则重新判定。它与双击序号关联共同生效，客户端否定标志不能创建这份证明。

## 5. 共享配方知识与可重建磁盘缓存

知识复用“怎样获得物品”，每次重新求解“当前材料如何分配”。四层所有权分别是：服务端权威配方/标签；两端共用的规范化和索引代码；各端按运行时配方世代复用的关系实例；仅服务端当前存档的磁盘缓存。

沿用 `Index`、`Entry`、`Requirement` 及引用表，共享产物→候选配方→输入需求→可选材料关系。AND/OR、重复槽和真实批次保留；相同需求共享候选，不共享数量预留。知识不递归展开整棵目标树，也不删除合法转换环。

需求键比较完整、排序后的匹配选项及组件语义，不能只用标签名、首个物品或对象 hash。固定平台内置的 Compound/Intersection/Difference Ingredient，只有普通叶、结构有界且已核实实际集合时才规范化；不能把所有 custom 一律拒绝，也不承诺通用第三方材料支持。

无法证明稳定语义的需求走原精确查询。尚未建完和完整计算后为空必须区分；半份关系不发布，超时不持久化成“永无配方”。求解器的局部排序不能修改共享候选列表。

缓存位于存档 `craftable/cache/recipe-knowledge-v1.json`，仅含版本、语义指纹及有界 ID/需求/邻接值。运行时句柄重新绑定；资源数量、坐标、权限、工作站现况、动态闭包、计划和令牌都不落盘。

语义指纹覆盖平台与规范化版本、支持配方的真实内容、输入/输出组件和返还物、已解析标签及影响支持范围的规则。确定性规范化只排序已知无序集合，不任意排序输入、效果序列或自定义数据。格式仍为 v1，规范化规则变更由指纹失配重建，无需旧缓存迁移。

| 持久缓存限制 | M4 边界 |
|---|---|
| 配方记录 / 规范化需求键 | 各 16,384 |
| 材料选项 / 需求→生产配方引用 | 各 262,144 |
| 单 ID / 身份快捷表 | 512 ASCII 字节 / 4096 项 |
| 正式文件 / 临时文件 | 各 16 MiB，分配前限长 |
| 新增知识估算驻留 | 起始上限 64 MiB，需另测实际峰值 |

缺失、指纹不符、损坏、非法引用、未知格式、读写拒绝或超限均放弃缓存并从索引重建。磁盘声明完整仍须核验邻接完整性；超出持久化范围只使用内存，不截断实际配方目录。

合成不等待磁盘。脏项合并写入，正常至多每 30 秒一次；临时文件校验后安全替换，失败保留旧有效文件。后台 I/O 只接收不可变值，每服务端最多一个在途写入和一个合并待写快照，过期世代不得覆盖新文件；关闭保存有界，丢失近期缓存只增加重算。

客户端默认从已同步配方本地建立关系，未增加图同步协议或客户端永久缓存。关菜单、换分类及资源变化保留静态图；重连/配方重载重绑。即使重载后内容指纹相同，也开启新运行时世代并废止旧授权。

本地目录还须与服务端的支持/规范化语义指纹握手匹配，包含标签、保护/准备规则、输出和返还物语义。仅有原版配方同步不够；指纹不匹配时不能发布本地可行证据。

## 6. 动态浏览、证据升级与资源同步

### 6.1 内容版本和授权租期

服务端活环境快照只在游戏线程存在，客户端接收最小授权值视图：会话、配方世代、有效规则、解锁/工作站、精确输入、主背包容量和稳定不透明来源引用。不得发送来源坐标、活句柄或未授权内容；已授权数量披露是该协议的明确能力。

内容版本比较真正影响可行性的规范值，包含资源、容量、保护、权限、规则及来源映射；扫描次数、时间戳、心跳和租期不进入计算身份。同内容复查只续期，保留已完成证据与闭包；真正内容改变则整份动态失效，静态知识保留。

来源引用对同端点/槽位稳定，替换、失权、恢复或双箱重组后废止旧引用；不同玩家/连接隔离。移动后需重新授权，数学内容相同可以复用计算，不能沿用旧来源权限。跨 tick 只保留有限值映射，不持有活容器。

事件通知配合有界周期复查，目标约 10 tick，覆盖漏斗及其他玩家操作。过期授权暂停计算与有效显示，不以延长 TTL 掩盖成本。分片扫描复制后再次核对一致性，再原子发布；冲突只有限重试或等待稳定。

### 6.2 完整证据与按需诊断

每条状态记录分别保存完整证据 `FEASIBLE / EXCLUDED / UNRESOLVED` 和可选诊断。充分排除完整制作不等于 `BLOCKED`，也不是部分计划；不支持、缺站、权限等前置拒绝另记。候选/深度/状态/时间省略均不能产生 `EXCLUDED`。

隐藏筛选使用 `FULL_ONLY`；可见、悬停、详情再按需补诊断。同身份完整成功直接复用；充分失败直接进入原核心诊断，避免重复完整搜索；未知不能跳过完整判定。诊断耗尽不覆盖已有完整成功或充分失败，且同身份被动停止。

完整身份不因 `partial` 意图位或查询用途变化而另起额度，部分阶段另核其策略；真实数量、约束、资源、容量和有效规则改变必须匹配新身份。同版本结论不按分类来回切换重新计算。

普通目录只留结论、证明种类和小型原因；悬停/详情最多两份有界方案，同目标共用。丢弃方案不等于丢弃结论，再提取当前单目标见证的成本应单计，不能假称布尔状态能还原步骤。

资源刷新期间可另保留陈旧图标显示表，只含状态、原因和列表顺序，并以 `~` 标记待更新；它与求解证据隔离，不含计划或充分失败证明，不可用于 MAX、见证或提交。显示表与结果合计受 2 MiB 上限约束。

MAX 成功方案可替换既有详情槽，入槽前验证交付与完整显示编码，不建立逐数量计划池。当前已发布显示另附最多 64 KiB、绑定精确意图/作用域的只读见证；后台 MAX 换槽不抹掉它，意图变化、失效、失败或新显示则释放。附件没有执行令牌。

### 6.3 分片调度与公平性

所有闭包、完整、诊断、静态准备、投影与 MAX 共用客户端 **2 ms/tick** 软截止。轻量任务提前完成后可继续派发，每 tick 最多 64 次，每次重新看同一截止点；新目标不另领时间片。

仅前台/隐藏各一份 continuation，同时推进一个。最多连续 3 个前台片，下一片给隐藏；隐藏队首保持到完成或累计耗尽。目标转可见复用原进度，悬停只替换最新候选，详情不能清除隐藏槽与公平计数。

授权、依赖及正常 tick 已就绪时，隐藏队首到下一次派发最多等 4 个客户端 tick；这是获片上限，不是完成上限。同步、闭包、暂停及不可抢占调用造成的等待单列记录，不能报作公平已达标。

单片到期保存 frontier、账本、visited 和累计支出原地续算；阶段耗尽释放 continuation、保留已有证据并停为未知。换分类、暂停续期、取消后返回及用途切换不清空已花预算；明确刷新可限流申请一次新尝试，传输重试不重启计算。关闭、换世代及真正撤权取消旧任务，迟到回调不能发布。

同资源版本只建一次动态存在性闭包，状态区分未开始、构建中、完成、未知。现物快路径可先走，其他目标不能把半份闭包当完整；准备累计额度用完即停止。M4 先扩大复用范围，不同时引入材料变化的局部结果失效。

### 6.4 有界同步与接收期限

浏览采用完整分块值投影，块数、长度、字节、摘要、会话和版本验证后原子发布。每连接只保留一份已发布及一份接收中快照；关闭、重载、断线、超时释放缓冲，半份资源不能参与求解。

同步合同将发送公平性与接收期限配套：最多 4 MiB，31 KiB 数据加至多 1 KiB 头、整块不超过 32 KiB，最多 133 块；全服 128 KiB/tick、玩家 32 KiB/tick，至多 8 份已准入传输逐块轮转，每份每轮最多一块。先完成数据/内存准入再发头，无名额时只发送有界等待消息。

以本地单调时钟、50 ms/tick 等值计时：新校验块才刷新 100 tick 无进展期限；固定总期限为 `100 + 4C` tick，C 为块数，最多 632 tick（31.6 秒）。重复块、心跳与租期不延长总期限；传完仍须持有新鲜授权，传输期限不是授权鲜度。

缺内容补传、停滞恢复与首次期限继承是 2026-10-23 的后续加固。现行传输约束和验证分别见[当前架构](02-architecture.md#transport)与[生命周期审计](17-production-behavior-audit.md#lifecycle)。

## 7. 交互与显示投影

详情沿用原菜单和槽同步，以目标在右、依赖向左的物品链呈现，附工作站、实际收支、数量、单一合成按钮与小型刷新入口。Esc 先关详情再退出背包；图不是第二个执行器。

已有材料、实际制作和缺料解释分别呈现。无法执行时也可展示可识别的普通配方路线；无配方的基础资源停为叶，循环或支持/预算边界明确截断。假设解释批次不进入库存、操作、净成本或确认授权。

同父节点只有精确物品/组件、所选配方、状态和依赖结构均一致才合并，数量相加并保留全部原需求路径；选择作用于全部代表需求。不同父节点各保留需求数量，共享上游来源只显示一次。

真实混合批次按精确材料及 `inputOrigins` 拆分 AND 输入，不变成材质 OR 轮播，也不能把每种木板接到全部原木。首材质只显示其自身数量；其他实际材质及混合配方保留警告，展示截断不能冒称全部同材质。

缺料解释先分配现物，再共享所选路线的假设整批余量，避免每个需求独立向上取整。默认省略无益同类再加工和精确逆转换往返；显式选择和真实压缩/拆解仍可显示。该整理只解释路线，不证明它可执行或全局最省材料。

OR 叶及候选卡按**完整**匹配集合比较，不凭前三项或 16 项显示前缀推断相等。冻结目录可提供有界只读集合证据：单 Ingredient 最多 4096 选项，每次新增键总计最多 16384；无证据/超限保守分开，不能截断完整集合键。它不进入协议、成本或审阅身份。

Tooltip 将同物同组件的输入、产出、返还物分别汇总，不相互抵消；实际净扣料看底部收支。候选卡保留真实网格，N 个同集合输入表示可各自任选，不是每种都要 N 个。文字逐行传入，不靠组件内换行；最多 40 行加省略提示，不截断执行计划。玩家文案避免实现术语，中英含义和参数同步。

图最多 256 显示节点，合并后统一整理和路由。硬边界是图标不重叠、材料位于消费者左侧、连线不穿无关图标、不形成假接；多输入共用一个入点、共享来源一个出点，无法避免的正交交叉留断口。

布局只做有界试排：小图最多 16 次同父换序、大图最多 4 次，跨父对齐最多 8 组、每组 2–8 个；每条连线最多 40 个局部通道候选。几何与绘制段随布局缓存，逐帧不寻路；无改善则恢复前一布局。复杂图的可辨连接优先，不承诺全局最短线或完全无交叉。

滑槽 M=0 时保留期望 1，禁止构造 1..0；搜索中保留选择，不把未知端点显示为实际 MAX。数量变化立即取消排队确认及旧 MAX 界面等待，匹配任务可转交最新请求但不重置额度；旧结果不能覆盖新意图。

## 8. 预算、容量与“未确定”

下表是 M4 基线的工作边界；软时间不能抢占一次 Minecraft 调用，估算内存也不是 JVM 堆的硬保证。

| 工作 | 限制与处理 |
|---|---|
| 根批次 / 实际步骤 / 深度 | 64 / 128 / 12；达到限制不能解释成材料不足 |
| 完整阶段 | 每身份累计 8 ms、2048 状态、单需求 16 候选 |
| 按需诊断阶段 | 充分完整失败后另 8 ms、2048 状态；不能借给完整搜索 |
| 闭包准备 | 每资源版本累计 8 ms，支出仍计入共享 2 ms/tick |
| 服务端准入 | 每请求 8 ms、全服同 tick 主动/被动合计 16 ms 软限，不因客户端两阶段扩额 |
| continuation | 各 4 MiB 保守估算、最多两份；分支分配前检查，取消为终态 |
| 动态会话 | 每连接估算 16 MiB、最多 16384 配方结论；方案/快照/续算一并计入 |
| 静态目录 / 服务端浏览会话 | 客户端连接估算 64 MiB / 全服估算 64 MiB，有界准入并轮转 |
| 资源 / 详情 | 最多 4096 来源栈；详情 128 步、32 缺口；动作帧与完整见证各沿 64 KiB 边界 |
| 余料实体 | 单事务最多 32 个，超限整单拒绝，不先扣料或只掉一部分 |
| UI 更新 | 常规结果每 4 tick 合并、每帧最多一次；失效及时处理 |

结构省略与累计耗尽分开记账：省略不必丢掉当前仍可验证的正例，但不完整否定及部分方案都不能授权。低优先备选/memo 可释放，累计时间、状态和深度不能重置。超限明确未知或拒绝，不执行计划前缀。

大批量可用保守必要步骤下界早停：同输入集合的尚需量除以已知单次最大产量向上取整，加根批次；重叠集合不相加，未知生产者或返还物可能供给时不用该项。超过 128 步只证明超出当前表示范围，不证明材料不足或精确 MAX。

MAX 可在首次数量查询原 8 ms 内尝试一份保守材料上界证书：对完整普通目录/闭包作有限非负赋权，验证每条可运行转换不增值，初始资源只计一次。目录不完整、返还物、转换/规模或时间无法证明时弃证，只保留下界；成功也不证明容量或消除步骤限制。

有证书时优先验证范围内最大的未检查数量。已证明更大数量成功可结束更小未知项对最大值的影响，却不宣称更小数量也能装下；更大的未知仍使 MAX 未确定。刷新复用同身份已完成证据，不新送预算。

完整请求另计扫描、复制、验证、提交、通知与 tick 尾延迟；不能用搜索耗时掩盖其他成本。浏览首批/全范围收敛、未知率、帧、网络及内存分别观测，普通原版 2 秒目标与大快照传输期限不是同一指标，实测结论见验收记录。

## 9. 最终选择与后续边界

最终结构选择了原索引共享知识、同核心客户端分片浏览和服务端完整见证验证：静态关系避免重复合并，同内容证据避免反复搜索，真实提交继续由服务端新鲜裁定。早期单击失败自动准备、逐步占真实背包、服务端逐目标轮询和五次被动从头重试均未进入最终行为；不再保留各次迁移的双实现或实施顺序。

M4 没有建设通用机器框架、全局最优求解、成功路线历史库、客户端磁盘资源缓存、静态图同步或材料变化后的局部结果失效。炉类、更多设备/来源、第三方配方与大规模低配/高 RTT 矩阵按后续路线处理，不由普通合成证据推定支持。

阅读当前产品约束应从 [02 架构](02-architecture.md)、[04 配置](04-compatibility-and-config.md)、[16 Pre-M5](16-pre-m5-transition.md) 进入；M4 已通过、曾失败和未证明的范围保留在 [15 验收](15-m4-acceptance.md)。后来的生产质量重构及测试专用门面清理也由后继记录说明，不能反写并声称为 M4 的历史交付。
