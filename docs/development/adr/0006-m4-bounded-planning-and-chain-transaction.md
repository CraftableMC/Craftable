# ADR-0006：M4 有界需求规划与整链单次事务

- 日期：2026-09-08。
- 状态：已实施。M4 于 2026-10-06 完成验收，预算校准与回归结果见 [M4 验收](../15-m4-acceptance.md)。
- 依据：沿用 M1 资源端点、M2 补偿事务和 M3 状态与菜单边界。整链规划、执行及交互见 [M4 实施说明](../14-m4-implementation.md)。
- 后续决策：[ADR-0007](0007-shared-recipe-knowledge.md) 扩充原配方索引的共享关系与静态磁盘缓存。[ADR-0008](0008-snapshot-scoped-client-planning.md) 允许向授权玩家同步最小资源值，并允许验证完整固定量见证来代替确认时的重新搜索。这些调整保留服务端对实际产量、来源、权限和容量的复验，搜索未知仍不能作为部分合成依据。

M4 当时的部分合成策略见下文。现行设置与免确认规则见 [Pre-M5 部分合成与白名单](../16-pre-m5-transition.md#partial-policy)。

## 背景

M4 启动时执行器仅处理一次普通原版配方。直接递归调用 `createOne` 会分别提交中间步骤，破坏整链失败恢复；为未来机器构造通用 RecipeAction 引擎又会让兼容层反向主导原版基础体验。M3 还观测到连续切分类后约 2 秒预览收敛，不能把单根递归预算直接乘以整个可见页。

旧草案将“一块木板制两根木棍”作为部分完成示例，不符合完整配方批次；“全局最大有用前沿”和最佳优先超图搜索也超出当前必要规模。

## 决策

1. 根目标保持具体配方，单击 C 只尝试一次完整根批次；同目标失败后的双击才是部分意图，长按不算。高级数量在物品链页滑槽选择，根产物绝不丢弃。
2. 普通配方索引 + 有界需求回溯 + 可回退精确资源账本；先找可行计划，暂不做通用机器适配器和全局最优求解。
3. 单步与多步共用一个计划/事务入口，有序步骤列表足够。整个请求一次托管/提交，逐步通知延后到全部物品成功提交后。
4. 部分完成须先证明完整目标因材料不足无法达成，再确定部分计划的产量与步骤界限。提交失败或超时不能把已找到的前缀变成部分计划。M4 当时默认 `EXPLICIT_SAFE`，只有显式请求部分合成时才按保守安全名单判断是否免确认。早期的单击自动准备方案未采用。
5. 预览只提供信息。显式确认使用限时一次性令牌，绑定请求意图和方案摘要。原决策要求确认时重新规划，完整见证经后续决策可改为新鲜验证。两条路径都不保存跨 tick 的可执行计划。
6. 规划预算同时约束根目标、批次与全服。原版调用不可抢占，因此以完整请求、客户端帧和服务端 tick 的测量判断单次合成、联合 MAX 和浏览优化是否有效。必要时只在主线程分片推进短期只读工作，避免为浏览引入持久任务系统。
7. 详情升级为物品链页：工作站状态、可编辑生产配方、数量滑槽与改链警告。图是计划/诊断投影，更换节点配方后重算全局材料分配，不新增服务器菜单、配方浏览器或第二套执行系统。
8. 净交付默认全部入包；可选只把溢出余料按原版主动丢弃表现生成实体。中间物不逐步占实际背包格，但只允许在一次有界同步事务内托管；不引入隐形持久库存。实体创建成功/失败清理须进入同次提交门禁，不能提交物品后不检查地丢余料。
9. 根配方和用户手选节点约束不因 MAX 静默改变；自动支路允许联合使用多种配方。最大量未证明时只报可行下界；路线改变先显示 ! 与实际消耗并确认。

## 拒绝的替代方案

- 连续提交单步：失败后难以区分合法部分完成与被迫半完成。
- 为需要的 2 根木棍拆分原版配方：改变材料成本与产量。
- 根据物品 ID 做永久 visited：会漏掉有库存起点的合法可逆转换。
- 搜索超时就自动做已找到的中间步骤：可能错过完整路径并过度消耗资源。
- 简单把全部 MAX 请求逐个按完整预算试一遍：使数量上限变成耗时放大器。
- 预览返回完整库存、确认接受客户端槽位计划：扩大信息暴露并破坏服务端权威。

## 代价和限制

不保证全局最优；复杂/动态配方与不完备搜索可能拒绝合法手动路径。非默认组件材料保护、请求开始时每步已解锁仍收窄自动支持范围，必须有明确提示。撤销逐步中间空间限制是一项公开的操作压缩取舍；余料生成真实实体后可丢失/被他人拾取，不承诺可追回。没有 Z 前显式快速准备只限低风险路径，用户/服务端可收紧到确认或禁止。

实际行为和验收范围分别见 [M4 实施说明](../14-m4-implementation.md)与[M4 验收](../15-m4-acceptance.md)。
