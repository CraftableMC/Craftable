# ADR-0005：M3 配方状态投影与临时背包工作台菜单

- 日期：2026-09-06
- 状态：已接受，已实现。
- 后续演进：配方书状态由批次查询改为授权快照下的客户端规划。现行浏览与执行边界见 [ADR-0008](0008-snapshot-scoped-client-planning.md)。
- M5 的左键详情入口和路线选择见 [ADR-0009](0009-recipe-route-selection-in-plan-details.md)。

## 决策与取证

原版 `ClientRecipeBook.setupCollections` 已经用同步配方建立目录；解锁、尺寸和可制作过滤发生在 `RecipeCollection`。因此复用目录对象，在 Craftable 背包界面活动期间投影其可见/可制作集合，离开时恢复原版计算。不会调用授予配方 API。

`RecipeBookComponent.updateCollections` 在可制作过滤前选择分类和搜索结果，`RecipeBookPage` 持有 20 个按钮。可见页优先，开启仅可制作筛选时也推进当前分类和搜索命中的隐藏候选，避免它们永远进不了列表。M3 当时按每玩家每 4 tick 一批、每批最多 32 个 ID 查询，同批共享一个环境快照。收到响应后在下一次界面 tick 更新集合，避免渲染中更换按钮导致索引越界。

缓存生命周期与业务状态分离。等待刷新时保留上次状态并标注待确认。创建响应使缓存待确认，同时用请求序号屏障拒绝创建前的响应；因为主背包输出容量影响全部配方，M3 保守使已有条目全部过期，但仅刷新当前视图，暂不建立材料依赖索引。

临时菜单继承 `CraftingMenu`，沿用原版 3×3、结果槽、配方放置、Shift 点击及关闭返还。保留原版 0–45 槽对象与 ID，末尾追加护甲与副手 46–50 槽。独立 accessor 只调整既有槽位的坐标，客户端与服务端使用同样布局。服务端确认工作台后通过 `openMenu` 打开临时菜单，保留原有的 `Player.inventory` 和 `inventoryMenu`。无工作台时仍使用原版 2×2。

屏幕复用原版配方书、人物渲染函数和背包背景。护甲、副手、人物与主背包保持原版坐标，九宫格在右上，输出置于其下，配方书按钮在副手上方。M3 初版屏幕继承 `CraftingScreen`，因此临时背包缺少原版背包的药水效果侧栏，也不符合原版 HUD 避免重复显示效果图标的类型判据。M4 于 2026-09-28 改为继承 `EffectRenderingInventoryScreen<CraftingMenu>`，补齐宽栏、紧凑图标、悬停提示和原版 HUD 的去重行为，继续沿用原版渲染与 NeoForge 效果事件。屏幕只负责衔接配方书的布局、输入和更新，无需新增 HUD Mixin。复测见 [M4 视觉与原版效果验收](../15-m4-acceptance.md#scenario-l)。

增强仅限生存和冒险。客户端输入、状态投影与服务端的预览、制作和菜单授权共用 `GameType` 判据。创造和旁观模式禁用增强按钮、临时菜单请求、配方状态预取及 C。切换过去时，临时菜单在下一游戏 tick 关闭并返还材料，随后回到创造目录或旁观 HUD。回到生存或冒险后，等玩家下次打开背包再判断是否使用临时菜单。

3×3 工作台失效使用原快照内工作台位置、维度与当前范围逐次复验；输入操作必须先检查 stillValid。关闭/死亡/断线沿用原版菜单生命周期。普通配方左键只放置背包材料或虚影，附近材料使用 C；2×2 上的 3×3 目标只展示原因，不把虚影放进错误槽位。

实体工作台 CraftingScreen 复用同一投影、预取、过滤、Tooltip 和 C；有效原版菜单自身也是 3×3 工作站。Tooltip 用独立简短原因翻译键合并状态，不复用“制作失败”通知全文。角标在物品层之上绘制，不改变 Toast。

## 边界

2026-09-07 视觉修订：合成网格维度不决定结果槽高亮尺寸。临时背包使用 16×16 结果内容区，既有 RecipeBookComponent Mixin 仅为 AmbientInventoryMenu 将原版 renderGhostRecipe 的大结果标记设为 false；实体工作台仍使用原版 24×24 外扩高亮。不复制 GhostRecipe/CraftingScreen 渲染，不改槽位、事务或协议。

M3 将单步执行器的合法上下文扩展到原版 `CraftingMenu` 家族，环境和事务仍独立复验。当时批次预览只返回状态，递归、数量与 MAX 在 M4 才接入。现行数量和执行边界见 [M4 实施说明](../14-m4-implementation.md#behavior)。

## 索引与刷新回归

模式切换撤销投影时，旧按钮还可能存活一个渲染帧。索引/空列表安全检查在支持的配方书屏幕内保持有效，不随能力开关提前退出；颜色、预取、C 则立即停止。关闭到 null 不触发 NeoForge Opening，因此使用 Closing 恢复原版集合，并在服务端完成关闭与返还后再于客户端 tick 进入创造目录，避免双重关闭或丢失切换意图。

用户提供的 `13.53.34` 与 `13.55.06` 崩溃报告显示：原版按钮重绑定为 1 个候选后，旧动画索引仍为 9 或 3。背景绘制回调早于原版重算动画索引，旧状态解析器此时调用 `getRecipe()` 导致越界。固定措施是：状态/目标选择不依赖动画帧；重绑定与所有原版读取入口校正索引，空列表直接停止该次操作；相同服务端结果只更新时间戳，不触发集合重建。开发专用客户端脚本连续 200 tick 切换分类/搜索/筛选，并注入上述旧索引作为回归。

2026-10-01 成品变体修订：“目标不依赖动画帧”只适用于同物同组件的替代配方，不能将桦木船帧自动替换成橡木船。目标与状态先按显示成品分组，再在组内择优。背景回调按原版已推进的动画时钟取得同一帧索引，所有读取入口仍校正索引并处理空列表。Shift+C 携带有界原版组上下文，玩家可在根节点候选卡上显式更换成品，重算整链、成本和 MAX。参见[批次与材质](../14-m4-implementation.md#22-批次材质与手选约束)和[配方书交互](../14-m4-implementation.md#interaction)。
