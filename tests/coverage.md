# 自动回归的风险与断言边界

本地回归与显式诊断统一使用 [run.ps1](run.ps1)，分类与实际参数见 [测试索引](README.md)。CI 沿用 Gradle 标准 `build` 生命周期，通过不代表本表各专项已全部执行。本表解释哪些错误必须使测试失败，以及各类结果能证明的范围。

## 1. 风险核对

| 风险：哪种错误必须使测试失败 | 主要反例/责任 | 不应被误作证据 |
| --- | --- | --- |
| 设置过滤组、诊断组、上次运行的日志被当成本次常规全量通过 | 入口自检及 Gradle 的本次运行身份/作用域校验；各组独立结果 | 进程退出 0、孤立 PASS 子串或上次运行的 `latest.log` |
| 测试文件或数据包名称与职责脱节 | `-SelfTest` 的命名正/反例及实际文件/数据包目录检查 | 名称符合规范就代表行为覆盖完整 |
| 配方书或制作预览未获当前授权便执行 | `PlanningReviewScenario` 的自然确认/权威审阅、令牌与见证反例；网络与执行 GameTest | 控件为绿色或数学上可合成 |
| 租约过期仍允许确认，或同值续期后因节拍早退而一直禁用 | 常规 planning 中的命名租约就绪回归；包含只读 MAX 等待边界，结束后恢复原状态 | 真实 MAX 请求、自然网络故障率或性能计时结果 |
| MAX 等待使新鲜授权禁用，或已同步 scope 内过期授权仍启用 | 全局 MAX 旁观的 fresh 正例与同 scope expired 负例；原同值租约配对、scope 退役/排队取消边界保留，失败才读上下文 | 只用 ready 过滤全部未就绪样本；把 LOW 注入后 NORMAL 尚未消费的旧 scope 控件状态当作同 scope 撤权失败；用单次调度样本概括所有运行条件 |
| 客户端展示的成本与服务器审阅不同却未经再次确认而消费 | `PlanningReviewScenario` 的真实审阅不匹配/第二次点击及库存、见证验证/零服务端重搜检查；`PlanningQuantityScenario` 的混材实际成本复核 | 私有状态中的“预计可用”公式 |
| pending MAX 的排队点击在 Esc 取消后仍制作或请求权威准备 | `PlanningQuantityScenario` 在真实高/低优先级 tick 边界捕获 MAX，取消后核对零产物及见证/完整/部分搜索计数不变 | 只检查 overlay 已关闭或直接清除队列字段 |
| 已打开详情页在个人余料偏好热改后仍用旧请求/令牌确认，或恢复偏好时复活旧回复 | `PersonalPreferenceLifecycleScenario` 在真实权威审阅后触发原按钮、检查新意图与旧回复隔离，然后等待自然重算继续实际确认 | 注入注册值等同真实 TOML 文件监听；没有余料溢出的夹具证明实体掉落行为 |
| 取消、Escape 或子页完成提前写文件；高级页保存被父页旧草稿覆盖 | 设置草稿/落盘/重开与高级页互通；`ConfigSettingsTest` 的 dirty-only、原子校验 | 只检查按钮标签、只检查内存 raw 值 |
| 远程/失效上下文、旧导航树或已切换模式的回调继续写规则/名单 | 专业真实布尔/整数/枚举/名单回调及合法捕获的 Undo/Redo/批量 Reset；旧父导航不能重拍身份，失效子页不传播 dirty、已脏顶层不保存；普通页上下文检查 | 仅按钮灰色、同值 Undo/Redo、未标脏页面没写盘，或注入身份等同真实 LAN 切换 |
| 界面读取本地可变 spec，而非当前连接的权威规则；旧回复覆盖新规则 | 设置规则同步的来源差异、序号、pending/重读与世界切换反例；规则 payload/限流单测 | 本机共享进程里两个值恰好相等 |
| 部分合成放宽个人/世界规则，空名单变成默认允许 | 模式/单名单纯测试、完整与空名单/表内外组合、`DirectPreparationGameTests`、真实 browse 规则同步 | round-trip 自循环单独证明权限正确 |
| 当前配置缺节/非法值未纠正、数值或名单越界、显式空表被补默认 | `ConfigCorrectionTest` 的实际注册 spec correction、范围/整表/空表反例；诊断缓存现行键、默认值与共享注册身份检查 | 字段总数、DEBUG 重载日志、把正常 spec 纠正当作已保留旧配置语义 |
| 列表加载中闪现临时 ID，旧写回调残留，材料合并串候选/组件 | 设置白名单 READY/非 READY、禁用未知 ID、父子草稿；完整候选与组件的正/反例 | 搜索行数或固定配方目录总数 |
| 原版列表入口覆盖控件、丢失 Option 映射或滑块延迟提交 | 设置导航中末行半宽/全宽/空行反例、身份/位置和实际保存 | 恰好有六个或七个字段 |
| 双语值、提示或材料清单越界/出现孤立结束标点，专业页重复范围 | 真实 Minecraft 字体、键盘/鼠标提示、缩放/小视口；注册元数据派生的范围与默认值 | 逐句复制翻译、截图存在即排版正确 |
| 翻译键缺失、格式参数不匹配、枚举选项说明混在同一行 | 实际资源的键/参数/枚举对应及 Tooltip 结构；实际控件排版 | 锁死所有句子的中文或英文措辞 |
| 按钮颜色借用其他材质的成功、隐藏项或陈旧结论，或仍靠原版底图组合出红/粉 | `RecipeButtonVisualStateTest` 的未知/当前结论优先级；`OutputVariantScenario` 的实际轮播、清空/恢复材料、授权过期、投影输入边界及真实背景像素，随后检查当前材质的 C/详情与精确消耗 | 仅检查枚举返回值证明实际渲染正确；投影输入断言等同真实筛选操作；粉色授予当前材质制作权限 |
| 未知、预算耗尽、结构/网络体量超限被当成可执行承诺 | 预算/调度/快照单测与 admission、见证、容量、批量 GameTest；完整客户端 unknown/取消回归 | 冻结时钟功能检查证明任意硬件都在 8 ms 内完成 |
| 失败消费、返还/余料丢失、共享批次重复扣料、回滚遗漏 | 事务/菜单资源/随机图/容量 GameTest 和实际 C/确认客户端；精确守恒与零消费反例 | 只检查最终结果码 |
| 炉型用错、燃料不足仍启动、余火与配方木材被重复使用、返还容器丢失 | `FurnaceScannerGameTests` 和 `FurnaceChainGameTests` 验证原版端点、实际投入和最终物品，含高炉减半燃烧时长 | 只验证炉类标志或仅核对计算出的燃烧 tick |
| 关界面停止加工，炉被占用仍前进，满包丢产物，或退款与成品同时发放 | `FurnaceProgressScenario` 走真实请求、关页和三种界面；`FurnaceJobsGameTests` 检查实际 tick、存档往返、满包和拆炉反例 | 界面截图代替守恒断言，或同进程存档往返代替崩溃恢复与独立重启 |
| 同一炉类产物显示多次、合并后选错路线、详情显示旧工作站、篝火要求燃料或熄灭后继续 | `FurnaceProgressScenario` 检查铁锭和牛排分组、真实 C 请求与当前工作站；服务端覆盖两种篝火的无燃料加工、熄灭暂停、再点燃和替换退款 | 只检查配方已同步或工作站枚举存在 |
| 新鲜资源变化后复用旧身份，或诊断失败污染已证明的完整结论 | `RecipeStatusLifecycleTest` 等 lifecycle/continuation 单测、`DiagnosticLifecycleScenario` 与真实 browse 规则变更 | 把必要的受控调度/预算适配误删为“反射多余” |
| 字节接收停滞后只续租而不恢复，或补传无限延长期限 | `SnapshotReceiverTest` 一次/首次期限/摘要/关闭边界；`BrowseTransferGameTests` 实际发送状态；`SnapshotResyncScenario` 实际请求→轮询→头/分块→解码反例，关闭补传分支应失败 | 仅测 retry helper、自然故障率、任意负载恢复保证或零客户端重算 |
| MAX 将较小数量容量失败误作所有更大量失败 | `PlanningQuantityScenario` 真实满背包两根骨头：一份失败、两份腾槽，MAX=2；单测保留未知上界/材料证书边界 | 仅注入 CREATED 就声称覆盖真实 MAX 调度 |
| 同步通知吞掉测试异常，防重入回归假通过 | `InteractionGameTests` 在监听器中收集每次新序号的重入结果，事务返回后在产品 catch 外断言 REQUEST_THROTTLED | 在会被产品 catch 的观察者内 assert，或旧序号只测到 replay |
| 缓存失配被当成功加载，或第二进程重新计算却冒称重启复用 | knowledge 的 warmup 实际保存→独立 restart 初始已载入/首次命中且零新增构建；文件格式/指纹反例由缓存单测及 GameTest 保留 | 文件存在即当前有效、旧版本缓存被正确拒绝即产品失败 |
| 图中不同材料/组件被误合并，几何线假接或丢选择路径 | graph 单测、投影/混材/routing 场景；相同与不同来源的配对反例 | 仅保留一个好看的截图 |
| 清理失败后污染下一组，配置/语言/窗口/鼠标、玩家/会话或监听器未恢复 | 设置状态恢复的成功/异常清理；场景 finally 与入口失败清理；`PlanningTestSupport` 的玩家/会话清理和 `TransactionTestSupport` 的固定资源快照身份 | 在恢复后才补做本应失败前就成立的断言，辅助方法调用成功就代表当前入口已被验证 |
| 打包混入开发客户端夹具或服务端装载客户端类 | baseline 构建及 knowledge 两个独立 JVM；开发夹具在独立 integrationTest 源集，main 不反向依赖其输出 | IDE 编译成功、单 JVM 缓存命中 |

## 2. 断言取舍原则

迟到普通 C 的 `CONFIRMATION_REQUIRED` 由 `LateConfirmationScenario` 以真实按键、真实服务端结果和 Netty 暂扣/放行覆盖：关闭原菜单后在新配方书页不打开旧详情；同页仍自动打开，且两端材料/产物保持不变。它会抓住删除展示归属检查或直接禁掉全部自动详情两种错误；展示隔离与执行授权分别断言。真实 LAN/换世界、受控管线停滞及令牌/规则/ACTIVE 敏感性检查的范围见[生命周期证据](../docs/development/17-production-behavior-audit.md#lifecycle)。

- 保留由风险决定的精确值：非法 wire 上限、合法范围端点、明确夹具的投入/产物守恒、一次请求/一次执行、正交几何端点、真实注册身份以及明确的模组 ID/品牌身份契约。这些值变化代表兼容、安全或行为变化，不是普通维护噪声。
- 注册项集合从现有 spec 派生，并检查每个期望控件的身份/作用域；不以整个页面字段总数阻止以后增加设置。特殊配置的缺席（例如个人没有私有名单、普通页不暴露诊断 TTL）仍是有意义的产品边界。
- 提示检查关注键、格式参数、选项逐项分段、元数据页脚和实际字体边界；保存/权限语义由行为测试覆盖，不由文案中的某个词“证明”。
- 私有 UI/调度状态没有公开测试面时，允许窄的测试适配；在职责内集中私有字段访问并写明所需行为，不在生产中新增可见接口，也不把所有私有字段镜像成第二个实现。
- 等待以具名步骤和就绪条件定位失败；入口负责分派，各场景拥有自己的局部状态和看门狗。自然采样次数、数量与计时计数按测试目的设置。截图、异步等待和恢复辅助只完成各自职责。

## 3. 证据适用范围

配置测试针对当前注册定义、空白名单和 16 种模式交集；调用显式提供策略、步数、序号与见证参数。完整失败、租约过期、规则收紧、材料/空位变化等反例，必须验证当前审阅、确认和提交入口的实际结果。

可选计时只属于显式诊断组。日志样本、冻结时钟、受控网络停滞和页面身份注入各有适用范围，不能合并成无诊断常规全量或任意负载保证。行为缺陷、修复依据和各批实际结果见[代码质量审计](../docs/development/17-production-behavior-audit.md)与 [Pre-M5 验收记录](../docs/development/18-pre-m5-acceptance.md)。

背包换位场景逐 tick 检查真实库存、颜色、列表和页码；失败时记录目标、授权/快照及材料上下文。一次独立复测通过不能解释另一批次的失败原因，报告中应分别保留失败与通过的范围。
